COMMIT FORMAT: 1) Conventional Commits (`<type>(<scope>): <imperative lowercase summary, max 72 chars, no trailing period>`), 2) Explicitly list staged files in `git add`, 3) Bulleted list of physical changes in imperative present tense ("Add X", "Fix Y", "Remove Z") with zero filler.</mandate></rule_block>

<catastrophic_system_bans>
<rule_block id="feature_sovereignty_mandate"><mandate>Performance optimizations MUST be structural. If optimizing latency or tokens requires dropping a functional feature or field expected in UI/DB, STOP and request "PERMISSION GRANTED to deprecate feature X to solve Y". NEVER autonomously delete or bypass cognitive features, metrics, or matrix metadata.</mandate></rule_block>
<rule_block id="the_zero_compromise_pledge"><mandate>Enforce strict Pydantic V2/Freezed schemas and 100% typed domain transit. If an expected key is missing, raise `AppException` and CRASH. NEVER implement backwards compatibility, fallback chains, defaults (`v.get('field', '')`), `hasattr()`, duck-typing (`isinstance(data, (dict, Mapping, MutableMapping))` or `BaseModel | Mapping`), `match/case dict`, `cast(Any, ...)`, naked dicts (`dict[str, Any]`, `list[dict]`, `TypedDict`), unannotated dict accumulators (`meta_dict = {}`), anonymous multi-value state tuples, `# noqa: QGR` suppressions, or recursive dict loops.</mandate></rule_block>
<rule_block id="the_duct_tape_ban"><mandate>Fix root causes instead of patching symptoms. If data is malformed, crash loudly. NEVER write duct-tape code, return empty arrays `[]` / default dicts `{}`, hide UI elements with `SizedBox.shrink()`, or catch-all with `try...except Exception:`.</mandate></rule_block>
<rule_block id="zero_service_layer_fallbacks"><mandate>Domain definitions MUST be strictly typed using Enum overrides, 100% Pydantic V2 DTOs, and `@model_validator`s. Services MUST crash Fail-Fast if the Domain Model lacks a guaranteed value natively. NEVER use raw dicts for state transit, duck-typing cascades (`isinstance(..., Mapping)`), `.get(key, default)`, `getattr(obj, key, default)`, or `if value is None: value = default` in Service/Controller layers. Raw dict conversions (`.model_dump(mode='json')` / `Model.model_validate(raw)`) are permitted EXCLUSIVELY at persistence and network boundaries.</mandate></rule_block>
<rule_block id="ban_anonymous_state_tuples"><mandate>NEVER use anonymous multi-value tuples (3+ elements or 2+ elements of identical primitive types), positional index access (`item[0]`, `res[1]`), or positional tuple unpacking (`a, b, c = ...`) for domain state transit or service returns. ALWAYS encapsulate multi-field return states in immutable Pydantic V2 DTOs (`ConfigDict(strict=True, extra="forbid", frozen=True)`). 2-tuples are permitted EXCLUSIVELY for `(payload, TokenUsage)` or `(key, value)` pairs at low-level utility boundaries.</mandate></rule_block>
<rule_block id="zero_compromise_cutover_mandate"><mandate>NEVER allow transitional dual-backend states, parallel storage drivers, or legacy fallback branches during platform migrations or storage cutovers. Platform cutovers MUST execute as atomic, single-pipeline transitions blocked by fatal AST guardrails (`QGR030`).</mandate></rule_block>
<rule_block id="the_no_legacy_mandate"><mandate>Legacy support is STRICTLY PROHIBITED. Ruthlessly delete obsolete code, fallback chains, and legacy test fixtures. NEVER maintain backwards compatibility with V1 structures, deprecated APIs, or legacy databases.</mandate></rule_block>
<rule_block id="database_schema_hallucination"><mandate>The SSOT structure in `seed_data.json` is immutable law. If an API response requires nested data, build a DTO (`WorkflowResponseDTO`). NEVER physically alter root persistence arrays in `seed_data.json` without a roadmap mandate.</mandate></rule_block>
<rule_block id="dependency_hallucination_firewall"><mandate>Zero-Trust dependency environment: solve problems using natively installed tools. NEVER autonomously propose new packages to `pubspec.yaml` or `uv.lock` without "PERMISSION GRANTED".</mandate></rule_block>
<rule_block id="windows_powershell_mandate"><mandate>Exclusively use native Windows 11 PowerShell commands and syntax (`;` to chain commands, `Remove-Item`/`del` instead of `rm`). NEVER use Unix/Linux commands (`rm`, `ls`, `cat`, `grep`, `sed`) or bash `&&` syntax.</mandate></rule_block>
<rule_block id="native_mcp_tooling"><mandate>ALWAYS prioritize native MCP tools (`view_file`, `grep_search`, `multi_replace_file_content`, `write_to_file`). NEVER use terminal text manipulation tools (`cat`, `grep`, `sed`) or instruct the user to run scripts manually.</mandate></rule_block>
<rule_block id="deceptive_persistence_mocking_ban"><mandate>NEVER mock repository persistence, save, or update methods with static return values or unverified `AsyncMock()` instances. Persistence unit/integration tests MUST verify stateful roundtrip behavior via subsequent get/fetch operations returning the updated domain model.</mandate></rule_block>
<rule_block id="database_persistence_git_ban"><mandate>NEVER execute `git checkout data/db_v2.json`, `git restore data/db_v2.json`, or git commands discarding runtime database modifications. ALWAYS preserve `data/db_v2.json` alongside test run artifacts.</mandate></rule_block>
<rule_block id="ban_heuristic_identifier_matching"><mandate>NEVER identify, filter, target, or resolve workflow steps, prompt blocks, matrices, execution artifacts, LLM providers, or credentials using hardcoded identifier tuples, keyword lists (`_MARKERS`, `_KEYWORDS`, `_NAMES`), substring searches (`marker in step.name.lower()`), prefix checks (`model_name.startswith("vertex_ai/")`, `"gemini" in model_name`), negative string filtering (`not k.startswith(...)`, `not val.startswith("$")`), `allowed_keys` shims, or heterogeneous string collections (`allowed_blocks`, `step_states`). ALL entity targeting, provider resolution, and metric evaluation MUST use typed DTO contracts, explicit Enums (`provider_type: LLMProvider`), dynamic Studio UI configuration (`OutputProfile.variance_target_block`), and positive ID-set resolution (`k in valid_id_set`).</mandate></rule_block>
<rule_block id="positive_id_set_filtering_mandate"><mandate>NEVER use negative string exclusion patterns (`not k.startswith("sys_")`, `not val.startswith("$")`, `not b.startswith("glb_")`) to filter entity IDs. ALL entity selection and step verification MUST use positive set membership against authoritative collections (`workflow_step_ids.issubset(record.step_states.keys())`, `target_wf.get_allowed_prompt_block_targets(all_steps)`, `targets.allowed_input_keys`).</mandate></rule_block>
<rule_block id="zero_backward_compatibility_planning_ban"><mandate>NEVER propose, plan, or implement "backwards compatibility", "legacy fallbacks", "defensive fallbacks", or "safe defaults". If a contract expects X, a missing or unmapped X MUST deterministically resolve to an empty set or trigger Fail-Fast (`AppException`).</mandate></rule_block>
<rule_block id="single_pipeline_invariant_mandate"><mandate>NEVER create bifurcated pipelines or parallel execution paths where strict logic coexists with legacy permissive logic. ALL execution paths MUST flow through ONE sovereign, deterministic pipeline.</mandate></rule_block>
<rule_block id="ban_drive_by_schema_mutations"><mandate>NEVER autonomously add new fields, optional attributes (`field: T | None = None`), or fallback keys to existing Pydantic DTOs or domain models as a drive-by fix for advisory AST warnings (`⚠️ WARN`). Pre-existing advisory warnings outside the active task boundary MUST be reported as technical debt.</mandate></rule_block>
<rule_block id="credential_hardcoding_ban"><mandate>NEVER hardcode API keys, bearer tokens, service account keys, secrets, or provider credentials in source code (`.py`, `.dart`), configs, test mocks, seed files, or git commits. Resolve exclusively via environment injection (`.env` via typed Pydantic `Settings`, `GOOGLE_APPLICATION_CREDENTIALS`, or Cloud Secret Managers).</mandate></rule_block>
<rule_block id="localhost_endpoint_hardcoding_ban"><mandate>NEVER hardcode local hostnames, loopback IPs, or test URLs (`http://localhost:8000`, `http://127.0.0.1:8000`) in app code, repositories, client services, or tests. Resolve strictly via centralized config (`settings.py` or Riverpod environment providers).</mandate></rule_block>
</catastrophic_system_bans>
