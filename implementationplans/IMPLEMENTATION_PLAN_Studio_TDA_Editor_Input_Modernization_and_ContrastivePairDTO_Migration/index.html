    Executive Summary

    The current Studio TDA (Test-Driven Assertion) Editor in @[client_app_v2/lib/features/studio/views/widgets/scale_editor_modal.dart] suffers from severe "Stringification Debt" and unconstrained user input formatting: 1. Contrastive Example Ambiguity: contrastive_example is stored as an untyped string (str | None) in @[backend_v2/models/v2_core.py#L155-L264], forcing authors in the UI to manually type arbitrary prefixes specifically ACCEPTABLE: "..." and UNACCEPTABLE: "..." inside an unvalidated single multiline TextFormField. Omission of either side corrupts the prompt compiler's few-shot grounding boundary. 2. Brittle String Delimiter Splitting: The frontend splits acceptance criteria and anti-patterns on newline characters (.split('\n')), and syntactic anchors on commas (.split(',')). Accidental linebreaks in a sentence fracture criteria into nonsensical tokens, while commas inside quotation marks produce corrupted anchor queries. 3. Cognitive Overload & Visual Clutter: All 12 TDA parameters are presented as a monolithic, unformatted vertical column of text inputs without visual hierarchy, semantic grouping, or active guidance on reversed hypothesis polarity (inverse_evidence). 4. Hardcoded Strings & Design Token Violations: Multiple helper labels and warning messages are hardcoded in Finnish with static colors (Colors.amber), violating the Dual-Axis Localization architecture. 5. Parochial Linguistic Validation: The editor uses a hardcoded, brittle regex RegExp(r'[äöåÄÖÅ]') for non-English detection instead of the Universal Linguistic Shield standard.

    This plan systematically eliminates stringification debt and aligns the TDA editor with desktop pro-tool architecture by: 1. Hardening contrastive_example into an immutable ContrastivePairDTO in @[backend_v2/models/v2_core.py#L155-L264] and @[client_app_v2/lib/features/studio/models/prompt_block.dart]. 2. Migrating all existing occurrences in @[backend_v2/seed/seed_data.json] via an automated migration script [NEW] @[scripts/migrate_seed_contrastive_pairs.py]. 3. De-stringifying the Studio UI into four dedicated modular sub-widgets under 150 lines: - [NEW] @[client_app_v2/lib/features/studio/views/widgets/tag_chip_input.dart] - [NEW] @[client_app_v2/lib/features/studio/views/widgets/dynamic_item_list_editor.dart] - [NEW] @[client_app_v2/lib/features/studio/views/widgets/contrastive_pair_editor.dart] - [NEW] @[client_app_v2/lib/features/studio/views/widgets/linguistic_shield_banner.dart] (with two-phase LinguisticShieldDetector). 4. Reorganizing the TDA editor into 5 visually distinct cards with elevation: 2, BorderRadius.circular(12), margin: EdgeInsets.only(bottom: 16), typography fontSize: 20, fontWeight: FontWeight.bold, pill-shaped contextual badges, OutlinedButton.icon actions, IconButton deletions, an explicit Virhetutka polarity warning banner, a robust PopScope dismissal protocol, and 100% bilingual .arb localization coverage per ki_workflow_context_governance.md and ki_desktop_pro_tool_studio_ux.md.

    User Review Required

    [!IMPORTANT] Database Seed Schema Migration & Production Cleanliness via run_seed: All 305 occurrences of contrastive_example in @[backend_v2/seed/seed_data.json] are deterministically migrated offline from legacy multiline strings ("ACCEPTABLE: ...\nUNACCEPTABLE: ...") to 100% valid Pydantic V2 ContrastivePairDTO JSON structures: {"acceptable": "...", "rejected": "..."}. The migration script ([NEW] @[scripts/migrate_seed_contrastive_pairs.py]) validates every atom against ContrastivePairDTO, fails fast on any parsing issue, and creates a backup. The resulting seed_data.json is guaranteed to be 100% clean and production-ready, allowing direct and flawless deployment to production databases via uv run python backend_v2/seed/run_seed.py <target_env> without any legacy strings, ad-hoc converters, or runtime fallbacks.

    [!WARNING] Pydantic V2 Fail-Fast Strictness: In @[backend_v2/models/v2_core.py#L155-L264], ContrastivePairDTO enforces min_length=10, strip_whitespace=True, and a @model_validator requiring acceptable != rejected. Any assertion attempting to persist identical strings, whitespace-only entries, or strings shorter than 10 characters will trigger a hard ValidationError preceded by structured logger.error dual-reporting with ErrorCodes.VALIDATION_FAILED.name.

    [!IMPORTANT] Desktop-Class Pro Tool Input Resilience (Uncommitted State Loss Prevention): TagChipInput implements the Dual-Shield FormField Architecture (per audit AUDIT-STUDIO-TAGCHIP-STATE-LOSS-001). When an author types a lexical anchor (specifically "kausaalisuus") and directly clicks "Tallenna" on the dialog AppBar or presses Ctrl+S without pressing Enter first, TagChipInput synchronously flushes and validates the uncommitted text buffer during form validation and save, preventing silent data loss.

    [!WARNING] PopScope Desktop Dismissal Protocol: Closing or cancelling the modal (via Esc, clicking outside, or the AppBar "Peruuta" button) routes strictly through a PopScope(canPop: false, onPopInvokedWithResult: ...) handler that computes composite dirty-state: final isDirty = _isModelDirty() || _hasPendingInputBuffers();. If uncommitted or unsaved changes exist, an AlertDialog confirmation is shown to prevent accidental loss of authoring work.

    [!WARNING] Zero-Legacy Mandate & Absolute Ban on Historical Trace / Dict Fallbacks: Per the_no_legacy_mandate and the_zero_compromise_pledge, backwards compatibility for obsolete execution traces and dictionary fallback tricks (specifically: isinstance(data, dict), permissive .get() chains, or fallback string parsing) is STRICTLY PROHIBITED. In @[scripts/diff_executions.py#L684-L1843], contrastive_example handling strictly expects the modernized ContrastivePairDTO dictionary structure (c_ex['acceptable'] and c_ex['rejected']). Any attempt to process legacy, un-migrated, or malformed execution traces must fail fast and loud. No legacy support or fallback code is permitted anywhere in the codebase.

    [!NOTE] Token Budget Impact & Prompt Fidelity Expansion: Expanding each atom's prompt payload to include structured <contrastive_grounding>, <acceptance_criteria>, <anti_patterns>, and <syntactic_anchors> increases per-atom prompt consumption by approximately 100-400 tokens (+2,000-12,000 tokens per evaluation call for 20-30 sampled atoms). This is an intended prompt fidelity enhancement (previously, LLMs evaluated assertions blindly without contrastive grounding or anti-patterns). The total prompt size remains well within the 128K context window and is strictly bounded by MatrixSamplingStrategy.

    [!IMPORTANT] Anonymous Tuple Eradication in Engine Transit (atom_flattening.py Line 102 & Lines 124-208): In @[backend_v2/hooks/atom_flattening.py], both the global unique_atoms collector at line 102 (dict[str, tuple[...]]) and local matrix_collected_atoms / all_matrix_atoms collectors at lines 124-125 (list[tuple[...]]) are refactored to store strongly typed FlattenedAtom instances directly (dict[str, FlattenedAtom] and list[FlattenedAtom]). All intermediate 5- and 6-element tuple constructions, positional tuple indexing ([0]..[5]), and tuple unpacking are eradicated per ban_anonymous_state_tuples.     """Structured contrastive calibration pair for TDA assertion boundary grounding.

    Attributes:
        acceptable: Textual exemplar satisfying the evaluation assertion.
        rejected: Textual counterpart demonstrating disqualification or boundary failure.
    """

    acceptable: Annotated[
        str,
        StringConstraints(strip_whitespace=True, min_length=10),
        Field(description="Textual exemplar satisfying the evaluation assertion."),
    ]
    rejected: Annotated[
        str,
        StringConstraints(strip_whitespace=True, min_length=10),
        Field(description="Textual counterpart demonstrating disqualification or boundary failure."),
    ]

    model_config = ConfigDict(strict=True, extra="forbid", frozen=True)

    @model_validator(mode="after")
    def validate_contrastive_diversity(self) -> Self:
        """Enforces that acceptable and rejected exemplars are distinct and non-empty.

        Raises:
            ValueError: If acceptable equals rejected or either exemplar is blank.
        """
        if self.acceptable.strip().lower() == self.rejected.strip().lower():

            logger.error("[V2Core] %s: %s", ErrorCodes.VALIDATION_FAILED.name, msg, exc_info=True)
            raise ValueError(msg)
        return self
