    Why SecretStorageMode.envelopeKms (Database Envelope Encryption) is the Primary B2B SaaS Standard

    1. 1-Step Customer Self-Service in the UI: Customer administrators do not have IAM access to the SaaS provider's Google Cloud console. In Flutter (Settings -> Organization & IAM -> BYOK & MCP Secrets), the administrator selects the provider (vertex_ai, openai, ai_studio, anthropic, azure_openai, local, or an MCP gateway), pastes the API key or service-account.json content into the input field, and clicks Save (PUT /api/v2/iam/organizations/{org_id}/secrets). The UI immediately clears the input field and displays only the irreversible 4-character masked_hint (****<alnum4>).
    2. NIST SP 800-57 Two-Tier Envelope Encryption (DEK + KEK):
    3. When SecretService.upsert_tenant_secret receives a plaintext secret in ENVELOPE_KMS mode, it generates a unique 256-bit cryptographically random Data Encryption Key (DEK) (secrets.token_bytes(32)) and a 96-bit nonce (secrets.token_bytes(12)), encrypting the secret payload in memory via AESGCM(dek).encrypt(nonce, plaintext_bytes, None) into ciphertext_payload.
    4. The per-record DEK is then wrapped (encrypted) using the system Key Encryption Key (KEK) — derived deterministically via HKDF-SHA256 from JWT_SECRET_KEY in local development or wrapped via Google Cloud KMS (KMS_MASTER_KEY_ID) in cloud production — producing encrypted_dek.
    5. Both ciphertext_payload and encrypted_dek are persisted in PostgreSQL 19 tenant_secrets. A compromised database dump cannot be decrypted without the runtime KEK held only in server memory / Cloud KMS.
    6. Sub-Millisecond Latency, Zero Cloud API Bottlenecks & 100% Local-to-Cloud Parity:
    7. Resolving and decrypting ENVELOPE_KMS records from PostgreSQL 19 tenant_secrets executes in sub-millisecond memory time without making external GCP Secret Manager HTTP calls on every DAG node execution, avoiding external rate limits and per-secret cloud billing across multi-tenant workloads.
    8. SecretStorageMode.cloudSecretManager remains available solely as an optional enterprise pointer mode (projects/<project>/secrets/<name>/versions/<ver>) for regulated enterprise tenants whose compliance policy mandates external secret vault residency, while SecretStorageMode.envelopeKms is the default and recommended best practice for both ROOT_SYSTEM and customer tenants.
