    IMPLEMENTATION PLAN: Refine and Modernize Tier 3 God Code Decomposition Workflow & Tooling

    Executive Summary

    Following the initial full execution of the modernized /tier3-god-code-decomposition workflow on backend_v2/services/auth.py and the subsequent decomposition of backend_v2/services/export_service.py, four structural improvement areas were identified to elevate decomposition quality, type safety, and automation ergonomics:

    1. Facade Class Size Limit & Immutable Dependency Injection:
    2. Problem: The AuthService package facade (__init__.py) swelled to 416 lines due to mechanical delegation and cross-cutting mutable property getters and setters (use_firebase, firebase_auth, _initialized_firebase).
    3. Modernization: Establish a strict architectural cap: package facade classes in __init__.py MUST NOT exceed 300 lines. Enforce immutable dependency injection in __init__, banning mutable property setters across sub-services unless explicitly required by an external library/mock interface.
    4. Package Facade Test Discovery & Audit Loop Targeting:
    5. Problem: Targeting backend_audit_loop.py directly at __init__.py historically caused ambiguity in locating the matching test suite.
    6. Modernization: Codify the execution rule: when auditing a package facade, agents must either target the entire package directory (specifically: backend_v2/services/auth/ --test) OR name the facade test explicitly as test_{pkg}_facade.py or test_{pkg}.py. Ensure scripts/backend_audit_loop.py candidate discovery documentation and handling reflect this standard.
    7. Strict Markdown Boundary [NEW] Tagging in Planning Workflows:
    8. Problem: Planning workflows frequently generated @-reference links for files that do not yet exist on disk without the [NEW] tag prefix, triggering fatal MBD003 errors during scripts/audit_markdown_boundaries.py validation.
    9. Modernization: Hardcode a zero-tolerance MBD003 gate in both @[.agents/workflows/tier0-create-plan.md] and @[.agents/workflows/tier3-god-code-decomposition.md], mandating that every planned file path not yet present on disk MUST be prefixed with [NEW] across all tables, lists, text references, and XML tags.
    10. Protocol-Driven Inversion for Inter-Bounded Context Collaboration:
    11. Problem: Cross-context service dependencies (specifically: OrganizationService requiring user creation capability from UserService) were resolved by passing loose callbacks (Callable[..., Coroutine[Any, Any, User]]), throwing away argument type safety and risking signature drift.
    12. Modernization: Mandate the use of lightweight typing.Protocol interfaces (specifically: UserCreatorProtocol) in services/[domain]/protocols.py instead of raw Callable functions. This guarantees strict compile-time checking of all parameter types and return values by MyPy.
    13. Reference Implementation & Empirical Proof in Auth Package:
    14. Proof of Invariants: Apply these principles directly to backend_v2/services/auth/: introduce [NEW] @[backend_v2/services/auth/protocols.py], update OrganizationService to consume UserCreatorProtocol, and refactor AuthService facade down from 416 lines to under 300 lines while preserving 100% test passing parity across all 116 tests.
