# System Context & Core Invariants

## 1. Executive Summary
The **System Context & Core Invariants** capability forms the foundational constitution of the Compound AI System. It establishes the absolute architectural invariants that govern how all other components (Backend, Frontend, LLM Engine) must behave. This capability exists to ensure **Forensic Sovereignty**, deterministic execution, and the total eradication of silent failures, LLM hallucinations, and undocumented state mutations.

## 2. Architectural Principles & Invariants

Quorum operates on strict structural boundaries, deterministic execution, and end-to-end auditability:

### 2.1. Universal Fail-Fast, Zero-Default Contracts & Strict Schema Validation
All data crossing system boundaries is strictly validated against immutable schemas (Pydantic V2 in Python, Freezed in Dart). Fallback chains, silent error absorption, and duct-tape workarounds are eliminated. Critical domain, identity, naming, relational, and creation DTO fields (`id`, `*_id`, `*_ids`, `slug`, `name`, `label`, `title`, `storage_mode`, `updated_by`, `created_by`, and `target_identifier`) never declare hardcoded scalar, string, or enumeration default values (`Field(default=...)` or non-`None` assignments in Python models, or SQL `DEFAULT` clauses in PostgreSQL 19 DDL), and service or API layers never mutate missing inputs into fallback defaults (`if value is None: value = default`), branch on test-environment variables (`PYTEST_CURRENT_TEST`), or maintain in-memory shadow fallback dictionaries (`self._local_*`, `self._deleted_*`, `self._memory_*`). If data is missing, malformed, or an expected state is not reached, the system halts immediately with an explicit `AppException` on the backend or renders an `AppErrorBoundary` on the client. Masking errors by returning empty arrays or hiding UI widgets is strictly prohibited.

### 2.2. Zero Permissive Typing, Primitive Obsession Eradication & Dot-Notation Transit
All domain, service, orchestrator, and hook layers enforce 100% typed transit using immutable Pydantic V2 DTOs configured with `ConfigDict(strict=True, extra="forbid", frozen=True)`. Naked dictionaries (`dict[str, Any]`, `list[dict]`, `TypedDict`), permissive type coercions (`cast(Any, ...)`), structural duck-typing (`isinstance(data, dict)`), dictionary pattern matching, type laundering via `TypeAdapter` with dictionary types (strictly banned under fatal rule QGR018), and permissive model configurations (`extra="allow"`, `extra="ignore"`) are eliminated. Type-checker and linter suppressions are completely eradicated across production, test, and script codebases: inline `# noqa` comments, type-ignore annotations (`# type: ignore`), and unchecked casts are strictly prohibited, backed by global type-checking configurations enforcing unused ignore warnings and standard-library configuration suppression ratchets.

Direct Pydantic DTO state transit is enforced across all pipeline stages: intermediate dictionary wrappers, local wrapper DTOs, and untyped runtime dictionary accumulators (`updated_dynamic = dict(...)`, `d[k] = v`) are prohibited. State reduction routes pipeline deltas, cognitive modifications, and evaluative matrix scores directly into strongly typed fields on `GlobalContextVarsDTO` (specifically `evaluative_matrices: dict[str, float] | None = None`) and `ExecutionMetadata` via pure functional updates (`.model_copy(update={...})`), preserving direct, unboxed DTO transit with zero intermediate dictionary wrapping.

Primitive Obsession across nested collections is completely eradicated: nested dictionaries (`dict[..., dict]`), primitive dictionary lists (`list[dict]`), untyped configuration dictionaries, and mutable worker telemetry bags are prohibited. Structured breakdowns, message payloads, aesthetic configurations, worker telemetry, and parser returns are encapsulated in dedicated, immutable Pydantic V2 DTOs (specifically `LevelStatsDTO` for level metrics, `LLMMessageDTO` for hydrated messages, frozen aesthetic DTOs in `sdui_rules` for visual hydrators, `StepTelemetryEntryDTO` for telemetry, and `ParsedMatricesResultDTO` for core parser outputs). In-memory state projection encapsulates folded step state strictly into `StepOutputContentDTO` instances with native mapping delegation rather than nested dictionaries, halting execution immediately with an explicit `AppException` upon encountering malformed state rather than constructing unvalidated fallback models. Pipeline state transit and trace events enforce closed payload unions and typed metadata DTOs (`TraceEventMetadataDTO`, `ProgressTracePayloadDTO`), eliminating intermediate double-serialization across execution boundaries. Residual open-JSON dictionaries in `SynthesisMetadataDTO` (using `ExecutionSummarySnapshot | None` and `dict[str, StepTelemetryEntryDTO] | None`) and `TranslationResponseDTO` (using `dict[str, str]`) are completely eliminated in favor of strongly typed DTO models.

All domain entities and API endpoints enforce Full-Duplex DTO Cross-Examination across the backend-frontend boundary: backend endpoint response models map 1:1 to strongly typed client Freezed DTOs configured with strict deserialization rejecting unrecognized keys (`disallowUnrecognizedKeys: true`). Client API clients and Riverpod state controllers transit strongly typed Freezed instances exclusively, eliminating raw map returns.

Downstream services access attributes exclusively via static dot-notation (`model.property`). Dynamic dictionary indexing, two-argument fallback lookups (`dict.get("key", default)`), lazy default fallback operators (`a or "default"`), and runtime reflection (`getattr()`, `hasattr()`, `setattr()`) are prohibited. Raw dictionary conversions and Open-JSON structures are confined strictly to an authoritative, frozen set of physical boundary files (quarantining low-level storage drivers, logging sanitizers, telemetry collectors, and foundational provider adapters) and authorized external specifications (OpenAPI, MCP protocols, and problem details representations).

### 2.3. Encapsulation of Multi-Field State (Anti-Tuple Architecture)
All multi-field return states and pipeline intermediate payloads are encapsulated into dedicated, immutable Pydantic V2 DTOs configured with `ConfigDict(strict=True, extra="forbid", frozen=True)`. Anonymous multi-value tuples (three or more elements, or two or more elements sharing identical primitive types) and positional tuple unpacking are eliminated. This prevents positional type blindness, where identically typed variables (specifically analytical reasoning versus source quotes) can be inadvertently swapped during unpacking while silently passing static analysis. Standard two-tuples are reserved exclusively for standard payload and token usage pairs or key-value pairs at low-level utility boundaries.

### 2.4. Centralized Configuration Sovereignty & Production Origin Security
Operational thresholds, concurrency limits, retry budgets, timeouts, token ceilings, section constraints, application versioning, listener ports, cloud deployment identifiers, and domain claims are centrally defined in the master configuration layer (`Settings`) using PEP 593 `Annotated` field definitions. Business logic, orchestrator pipelines, API routers, background workers, and prompt templates resolve limits and runtime metadata strictly from this single authoritative configuration source rather than hardcoding operational values in execution code:
- **Application Version, Cloud Run Listener Ports & Socket Timeouts**: The master configuration defines `app_version` (normalized via `strip_whitespace` and bound directly to the `FastAPI` application instance and `HealthCheckResponseDTO.version`), `port` (`ge=1`, `le=65535`, bound via `AliasChoices("port", "PORT")` for the HTTP API listener), `worker_health_port` (`ge=1`, `le=65535`, bound via `AliasChoices("worker_health_port", "WORKER_HEALTH_PORT", "PORT")`, defaulting to `8081` locally so the background worker health listener never collides with the local `uvicorn` server on port `8000` while automatically binding the container runtime `PORT` environment variable in cloud deployments), and `http_client_timeout_seconds` (`ge=0.1`, `le=60.0`) governing bounded HTTP client and worker health probe socket reads.
- **GCP Regional & `qrum.ai` Domain Claim Normalization**: The master configuration defines `gcp_project_id` (`cognitive-quorum`, bound via `AliasChoices("gcp_project_id", "GCP_PROJECT", "GOOGLE_CLOUD_PROJECT")`), `gcp_region` (`europe-north1`), `primary_domain` (`qrum.ai`), `jwt_issuer` (`https://api.qrum.ai`), `jwt_audience` (`https://qrum.ai`), and `frontend_app_base_url` (`https://app.qrum.ai`). Domain and URI settings (`primary_domain`, `jwt_issuer`, `jwt_audience`, and `frontend_app_base_url`) apply `BeforeValidator(strip_trailing_slash)` (`v.strip().rstrip("/")` when `isinstance(v, str)`) with non-empty length bounds, guaranteeing that dynamically interpolated RFC 7807 validation problem type URIs (`f"{get_settings().jwt_issuer}/errors/validation-failed"`) and frontend invitation or task links never contain malformed double slashes (`//`). Furthermore, `postgres_dsn` binds `AliasChoices("postgres_dsn", "POSTGRES_DSN", "DATABASE_URL")` for direct Cloud Secret Manager injection, and Vertex AI Application Default Credentials (ADC) detection in `model_post_init` and `enabled_providers` inspects `VERTEX_PROJECT_ID`, `GOOGLE_APPLICATION_CREDENTIALS`, `GCP_PROJECT`, and local service account key presence.
- **Consolidated Production CORS Origin Lockdown**: Cross-Origin Resource Sharing origins (`cors_origins`, enforcing `min_length=1`) are passed directly from `Settings` to `CORSMiddleware` without wildcard fallback branches. Within `_enforce_environment_limits`, when `environment == "production"`, if `cors_origins` is not explicitly provided in `model_fields_set`, the configuration automatically locks `cors_origins` to the closed domain set `[f"https://{self.primary_domain}", f"https://app.{self.primary_domain}", f"https://studio.{self.primary_domain}"]` (`["https://qrum.ai", "https://app.qrum.ai", "https://studio.qrum.ai"]`), avoiding comma-delimiter collisions with JSON list decoding in cloud CLI environment flags. Unconditionally in `production` mode, `_enforce_environment_limits` verifies that `cors_origins` is non-empty and that every origin starts with `"https://"`, contains no wildcard character (`"*"`), does not end with a trailing slash (`"/"`), and specifies a non-empty host (`len(origin) > len("https://")`), raising `ValueError` immediately on any violation.

### 2.5. Universal Single Source of Truth (SSOT) & Data Normalization
Every piece of state, telemetry metric, token count, pricing registry, financial cost, configuration mapping, and entity relation maintains exactly ONE authoritative source and ONE canonical storage location across backend and frontend. Data is maximally normalized at rest and in transit, with zero duplicate sub-dictionaries, secondary shadow tables, local backup dictionaries, or parallel fallback access chains. If data or metadata is missing from the canonical SSOT, the system halts immediately with an explicit exception rather than guessing or maintaining shadow state.

### 2.6. Repository Reconstitution Firewall, Hexagonal CQRS Ports & Zero-ORM Persistence
Persistence repositories and database adapters operate as strict anti-corruption layers governed by a Zero-ORM architecture and Hexagonal Command Query Responsibility Segregation (CQRS) ports:
1. **Hexagonal CQRS Port Segregation & Sovereign Storage Driver**: Persistence operations are partitioned across five runtime-checkable protocol ports (`GraphMutationPort`, `TopologyResolutionPort`, `CausalReasoningPort`, `EntityPersistencePort`, and `QuorumUnitOfWork`) alongside protocol-level Unit of Work factory registration (`UnitOfWorkFactory`, `register_default_uow_factory`, and `get_registered_uow_factory`), enabling domain services to acquire transactional `QuorumUnitOfWork` contexts without importing concrete driver or factory modules. Write-only proposition wave mutations, read-only topological Kahn wave queries, read-only Toulmin structural falsification joins, and core domain entity CRUD (including physical document deletion `delete_collection_document`, parameterized batch seeding `seed_collection_batch`, and table row-count verification `verify_seed_table_counts`) are isolated into dedicated port contracts coordinated atomically by `QuorumUnitOfWork`. Within `PostgresEntityAdapter`, relational SQL statements and row reconstitution routines are partitioned into cohesive domain stages covering column coercion and upsert execution, identity and system configuration tables, prompt block and step blueprint tables, workflow and output profile tables, execution and report artifact/binary tables, and batch seeding and collection query operations. All 16 domain repositories (specifically and exhaustively: `AgentRepository`, `AuditRepository`, `ComponentRepository`, `ExecutionPersonaRepository`, `ExecutionRepository`, `ExtractionProtocolRepository`, `IdentityRepository`, `KnowledgeRepository`, `MatrixRepository`, `OutputProfileRepository`, `PromptBlockRepository`, `ReportArtifactRepository`, `RoleRepository`, `SystemRepository`, `TaskBlueprintRepository`, and `WorkflowRepository`) route through `PostgresStorageDriver` implementing `StorageDriver` over `PostgresPoolManager` and `PostgresEntityAdapter`. Persistence factory resolution enforces `StorageBackend.POSTGRES` as the single sovereign backend pipeline, rejecting non-PostgreSQL backends immediately with `ConfigurationError`.
2. **Zero-ORM Binary Wire Serialization, Direct Subscript Projection & $O(1)$ Primary-Key Lookup**: Object-Relational Mapping (ORM) frameworks, implicit identity maps, and lazy-loading proxies are prohibited. On PostgreSQL 19 connections (`asyncpg`), JSONB columns serialize and deserialize directly between Rust-backed Pydantic V2 buffers and the PostgreSQL binary wire protocol via a `\x01`-prefixed `pydantic_core` (`to_json` / `from_json`) codec. Database rows are typed via a standalone `AsyncPgRecordProtocol` (`__getitem__` without `Mapping` inheritance) and projected via direct column subscript access (`row["column"]`) into immutable `ConfigDict(strict=True, extra="forbid", frozen=True)` Pydantic V2 models (`PropositionNode`, `DependencyEdge`, `NodeDraft`, `EdgeDraft`, `FalsifiedClaimMatch`, `ReportBinaryPayloadDTO`). Intermediate dictionary conversions (`dict(row)` or `**row` unpacking) never occur inside persistence adapters, and 1:1 DDL column-to-DTO attribute naming parity is statically enforced across all 15 tables. Repository primary-key lookups (`get_organization_by_id`, `get_user_by_id`, `get_invitation_by_id`, `get_by_id`, and `get_config`) execute exclusively through $O(1)$ `driver.get(collection, id)` (`WHERE id = $1::uuid`), while `.query(..., [Filter("id", "==", ...)])` primary-key filtering is statically banned under `ZORM007`. Multi-tenant isolation operates at two layers: explicit `WHERE organization_id = $1` parameterized SQL predicates paired with transactional `SET LOCAL quorum.current_org` and `RESET quorum.current_org` connection cleanup inside `PostgresUnitOfWork`. Before running schema verification (`verify_schema_tables`), both application startup and database seeding invoke `uow.pool_manager.apply_migrations()` to execute idempotent `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` column evolutions against existing persistent volumes (`ZORM007`).
3. **Stateful In-Memory Testing Parity**: Testing pipelines enforce identical persistence invariants: mock-emulation layers, dynamic proxy facades, and deceptive mock persistence calls (`AsyncMock`, `MagicMock`, `.return_value`, `.side_effect` assignments) on repository or Unit of Work interfaces are prohibited across test suites. Unit and integration tests verify persistence behaviors strictly through stateful in-memory fakes (`BaseInMemoryRepository`, `InMemoryUnifiedWorkflowRepository`, `InMemoryUnitOfWork`, `InMemoryEntityAdapter`, `InMemoryAsyncPgPool`, and `PostgresStorageDriver(auto_initialize_pool=False)`) bound via `register_default_uow_factory` and featuring real collection and relational table state (including physical deletion via `delete_collection_document`), cycle detection, and deterministic fault injection (`inject_fault`), asserting that modifications saved to persistence survive true stateful roundtrip queries.

### 2.7. Cross-Domain Contract & Semantic Parity
Field and variable names are permanent architectural contracts. Nomenclature between Python backend and Flutter frontend remains 1:1 identical at the serialization layer (backend `snake_case` mapped to frontend `camelCase` via explicit JSON annotations). Renaming DTO fields, altering properties for subjective preference, or swapping domain concepts is strictly prohibited; all names and terms are derived directly from the SSOT.

Enumeration definitions enforce strict cross-language bidirectional parity: domain enums (specifically `StepFilterScope` with members `specialists`, `system_core`, and `all`) are mirrored 1:1 between Python `StrEnum` and Dart `@JsonEnum()` with explicit `@JsonValue` annotations and typed backend value getters. Bidirectional parity testing statically verifies value sets across language boundaries, guaranteeing zero casing drift or missing member definitions.

Administrative Studio interfaces enforce server-driven segregation between domain specialist steps and foundational system core step blueprints (`is_system_core`). Ingress API routers delegate filtering directly to domain workflow services (`StudioWorkflowService.list_steps`), while client-side dashboards operate as pure Dumb Painters driven reactively by controller filter scope selection, rendering segmented selector controls with localized error boundaries.

### 2.8. Opaque ID Hydration, Canonical `id` Relational Sovereignty, Universal Entity Naming & Informational `slug` Boundaries
To prevent LLM token bloat and hallucination from long database UUIDs, the prompt compiler substitutes raw identifiers with short, deterministic attention anchors (specifically: indexed atom and source identifiers `a0` and `src_0`). After execution completes, the service layer hydrates these short aliases back to their physical database identifiers.

Across the boundary between external APIs and relational storage, entity identifiers follow a bijective RFC 9562 UUIDv7 and Opaque Stripe ID bridge (`PrefixedUUID7`) governed by three structural invariants:
- **External API & Domain Representation**: Every persisted domain entity uses a single canonical primary key field named `id`, formatted in external contracts and domain models as a prefixed 32-character lowercase hexadecimal Opaque Stripe ID (`OPAQUE_STRIPE_ID_REGEX`: `nod_...`, `edg_...`, `exe_...`, `rep_...`, `wf_...`, `sp_...`, `blk_...`, `op_...`, `sys_...`, `usr_...`, `org_...`, `inv_...`, `sec_...`, `tsk_...`) with zero alternative primary key field names (`uuid`, `pk`, `primary_key`, `entity_id`, `node_id`, `edge_id`, `report_id`, `workflow_key`, `step_key`, `block_key`).
- **Database Storage Representation, Universal 32-Hex UUIDv7 Generation & Relational Binding**: Relational primary and foreign key columns store native 16-byte K-sortable RFC 9562 `UUID` values generated by `uuidv7()` in PostgreSQL 19 (`id UUID PRIMARY KEY DEFAULT uuidv7()` validated by `CHECK (uuid_extract_version(id) = 7)`) or `generate_uuid7` and `generate_uuid7_opaque_id` in Python (backed by a thread-safe 12-bit monotonic `rand_a` sub-millisecond counter and 62-bit CSPRNG entropy). Identifier generation in `generate_opaque_id` delegates universally across all `EntityPrefix` members to `generate_uuid7_opaque_id`, preserving B-tree append locality while translating losslessly via `parse_prefixed_uuid7` and `format_prefixed_uuid7`. All cross-entity relations bind exclusively through canonical `id` fields: via `REFERENCES <table>(id)` in PostgreSQL 19 and via `*_id` or `*_ids` fields referencing target `.id` in Python, JSON, and Dart models. On the Flutter client, `StrictOpaqueIdConverter` enforces strict 32-hex validation (`^[a-z]{2,5}_[a-f0-9]{32}$`), while `generateOpaqueUuid7` generates transient client sub-entity identifiers (`sr_`, `grp_`, `tda_`, `blk_`, `sp_`) as 32-character lowercase hexadecimal RFC 9562 UUIDv7 strings. Legacy version-4 UUID generators and 8/16-hex identifier truncations are completely eradicated across both backend and frontend.
- **Universal Human-Readable Entity Naming & Informational-Only `slug` Demarcation**: Every named domain entity table (`organizations`, `users`, `system_configs`, `prompt_blocks`, `steps`, `workflows`, `output_profiles`, and `report_artifacts`) and every seed collection entity declares a required non-empty human-readable display field (`name`, `label`, or `title`) for UI presentation, strictly separated from `id` (used exclusively for identification and relational binding) and `slug` (optional technical namespace metadata). The `slug` attribute is strictly informational and is prohibited from acting as a primary key, foreign key, query filter (`Filter("slug", ...)` or `QueryCondition("slug", ...)`), SQL `UNIQUE` / `WHERE` / `JOIN ... ON` predicate, dictionary lookup key (`{x.slug: ...}`), string literal or identifier comparison (`x.slug == "literal"`, `x.slug == target_id`, `x.slug in allowed_set`), or diagnostic identifier in logger and `AppException` calls (`QGR031`, `ZORM004`, `ZORM007`). Metadata-to-metadata equality checks (`existing.slug == payload.slug`) are permitted exclusively for change detection.

### 2.9. Dynamic Workflow Input Encapsulation
Dynamic workflow inputs declared in the ontology database are encapsulated inside strongly typed container DTOs (`ExecutionInputsDTO`, leveraging closed union types `IngressInputValue`). Services, hooks, and context builders accept this typed container directly, maintaining complete type safety across boundaries while preserving runtime workflow dynamism without requiring code deployments.

### 2.10. Server-Side UI Sanitization (Sandwich Architecture)
To ensure output stability, a deterministic interceptor layer sanitizes and validates LLM generation before payload delivery to the client. It strips conversational artifacts, validates markdown structures, and ensures complete compliance with expected Server-Driven UI schemas.

### 2.11. Dual-Reporting Protocol (RFC 7807)
Every backend exception (`AppException`) logs a structured error with exact logical error codes, parameters, and forensic trace identifiers before propagating. This provides immediate forensic traceability in monitoring systems while returning safe, structured problem details representations to client interfaces.

### 2.16. Evidence Extraction Invariants, Provenance Sovereignty, & Anti-Pattern Falsification
All evidence extraction and provenance gating across the architecture enforce four non-negotiable invariants:
1. **Anti-Ellipsis Lexical Anchoring & Multi-Segment Bounding:** Candidate evidence quotes (`quotes` / `source_quote`) consist of ordered bounding span vectors ($\vec{\mathcal{C}}_i$, $1 \le m \le 3$) of unbroken character substrings directly from the source material, with monotonic spatial ordering ($s_1 < e_1 < s_2 < e_2 \le s_1 + 1\,000$) and single-document buffer boundary isolation. Splicing separate sentences with ellipses (`...` or `…`) within any individual quote segment is prohibited, preserving exact lexical matching (`str.find`) in downstream verification engines without false-negative validation failures.
2. **Deterministic Anti-Pattern Falsification:** For existential error radars (`inverse_evidence = true`), legitimate contextual exceptions (specifically faithful summarization of an explicitly cited external research report) are formally governed by deterministic `anti_patterns` within the atom definition. This eliminates meta-cognitive oscillation caused by unconstrained contextual overrides, ensuring consistent, repeatable evaluation.
3. **Endorsed Deliverable Provenance (`ExpectedInput.is_endorsed_deliverable`):** Deliverables configured with endorsed deliverable provenance designate the work as the candidate's formally submitted output. The candidate is fully entitled to incorporate AI-assisted phrasing, executive terminology, and domain jargon developed during the workflow without triggering Echo Parroting penalties, while observation-layer performative pattern scanning remains active for transparent telemetry.
4. **Multi-Stage Lexical Validation & Multilingual Morphological Stemming Sequence:** Lexical citation verification across source documents executes through a deterministic 4-stage pipeline in `AnchorValidationService._is_lexically_valid`:
   - **Stage 1 (Exact Substring Fast-Path):** Executes $O(N)$ normalized string matching (`str.find`) over Unicode NFKC and diacritic-stripped text context.
   - **Stage 2 (Length-Weighted RapidFuzz):** Evaluates string distance against locale-specific fuzz thresholds (`get_lexical_fuzz_threshold(locale)`).
   - **Stage 3 (Morphological Stemmed Sequence Verification):** Resolves grammatical inflections (specifically Finnish noun cases, Swedish declensions, English conjugations, German endings, and Hungarian agglutinations) via pure-Python `StemmerService` wrapping Martin Porter algorithmic Snowball stemmers. It enforces:
     - *Candidate Window Discovery*: Scans source text for contiguous windows anchored to matching content stems.
     - *Window Contiguity Guard*: Prohibits token spans exceeding quote length plus padding (`MAX_WINDOW_TOKEN_PADDING = 15` tokens or equivalent character bounds `quote_char_len + 150` characters), preventing stitching disparate words across distant paragraphs.
     - *Entropy Gate*: Preserves short words strictly under 4 characters (`MIN_STEMMABLE_WORD_LENGTH = 4`) without morphological alteration, preventing false-positive stem collisions on short acronyms, stop words, and prepositions.
     - *Decoupled Strictness Invariant*: When lexical strictness is absolute (`default_lexical_strictness_level >= 100` or `tier_threshold >= 100.0`), Stage 3 is unconditionally bypassed, enforcing 100% exact character matching. Under decoupled strictness ($\zeta_{\text{lex}} < 85$), Stage 3 operates independently of the matrix scoring dampening rigor.
   - **Stage 4 (Coverage Safety Net):** Evaluates longest contiguous subsequence coverage via `difflib.SequenceMatcher` against `ValidationThresholdRatio.COVERAGE_SAFETY_NET`.
   If all stages fail, the verifier raises `SemanticEvidenceError` immediately, eliminating hallucinated citations with zero permissive fallbacks.

### 2.21. Autonomous Causal Discovery, Topological Fault Attribution & Fair Scoring Arithmetic
Autonomous argument mining operates over unstructured source documents through sliding window linking (`SlidingWindowLinker`) and causal discovery execution (`CausalDiscoveryEngine`), constructing a directed proposition DAG (`LinkedAtomGraph`) evaluated through `TopologicalEvaluator`. The causal discovery pipeline adheres to seven structural invariants:
1. **Thread-Isolated Pre-Flight Cycle Defense**: Prior to wave execution, cyclic reasoning is detected in a worker thread (`asyncio.to_thread`) via NetworkX, flagging circular claims with `ExecutionStatus.SYSTEM_ERROR` without blocking the async event loop.
2. **Kahn's Discrete Wave Evaluation**: Argument nodes evaluate in discrete topological waves preserving the Local Causal Markov Condition, where all causal antecedents resolve before dependent claims execute.
3. **Topological Fault & Blame Attribution**: Upstream root causes are isolated from secondary cascading failures via bounded upward graph traversals along causal dependency edges (`in_deps`). ### 2.22. Topological Code Decomposition & Test Invariance
System refactoring and module decomposition adhere to topological AST boundary extraction and test preservation invariants:

### 2.23. Network Egress Security, SSRF Firewall & Protocol-Agnostic Tool Transport
Outbound communication with external Model Context Protocol (MCP) gateways and network endpoints enforces strict egress boundaries and transport security:
1. **SSRF & DNS-Rebinding Firewall**: All destination endpoints pass through non-blocking asynchronous address resolution in worker threads prior to socket allocation.
