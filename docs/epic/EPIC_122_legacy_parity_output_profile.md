## 1. Goal Description & Background (Objective & Problem Statement)

> [!CAUTION]
> **EPIC 121 STRATEGIC DEPENDENCY**
> EPIC 122 MUST be implemented completely BEFORE EPIC 121. The complex Output Profile payloads generated by this Epic (`content_blocks`, multi-layout sequences) are required as test data to stress-test the Admin Studio editor built in EPIC 121.

**Objective**: The user requires a PDF output that perfectly matches a historical legacy report format (e.g., pre-EPIC 110/120) but implemented strictly using the modern "Dumb Painter" SDUI architecture. 

> [!IMPORTANT]
> **ZERO EXCEPTION MANDATE (UNIVERSAL COMPLIANCE)**
> ALL reports and printouts (both PDF and Flutter UI) MUST be generated exclusively using this newly defined SDUI architecture pipeline. There are NO exceptions. Legacy bypasses, hardcoded UI logic that ignores the payload, or "backdoor" renderings are strictly forbidden. Every single report must flow through this unified data contract.

**Specific Requirements**:
1. **Header with Expanded Metadata**: The top header (green box) must display the core titles and an expanded set of general metadata (Timestamp, ID, Organization, plus new fields like User, Scoring Engine, and Strictness). Titles are resolved from the `I18nText` locale resolution chain (English master → target locale).
2. **Fixed Content Sections Inside the Summary Card**: Static text preambles must be injected directly *inside* the summary layout card via `I18nText`-wrapped `content_blocks`, immediately preceding the AI-generated synthesis text. The preamble text is defined in the master `en` locale and translated to target locales (e.g., `fi`).
3. **User Role in Synthesis**: The user's role must be integrated as part of the synthesis block flow. The LLM synthesizes the role dynamically in the **target output language** based on the `OutputProfile.language` field — no hardcoded locale strings in prompts.
4. **2D Scatter Chart Layout**: A dedicated layout block for detailed scoring must render a synthesis box and a 2D scatter chart between the global summary and the matrix.
5. **Dynamic XAI Extensions**: Output extensions (e.g., justification, coaching, counter-arguments) must be mapped dynamically from the backend using `extension_labels` with `I18nText` — no hardcoded locale-specific titles in Jinja or Flutter.
6. **Unified Matrix Tables**: All matrix printouts must display row explanations, scores, and atom hit distributions in a single unified table. Column headers are resolved via `matrix_column_labels` `I18nText` objects.
7. **View-Only Matrix with External Edit Link**: The matrix will be rendered as a strictly view-only component in both Flutter and PDF to guarantee 100% visual parity (matching the exact table structure in the provided reference image). Atom overrides will NOT be handled via interactive UI elements inside the matrix rows; instead, editing capabilities will be provided via a separate external link.

**Problem Statement**: The legacy PDF relied on hardcoded Jinja logic to achieve this layout. Under the new architecture, `report_template.jinja2` is a dumb consumer. Therefore, all these requirements must be satisfied by carefully configuring the `OutputProfile` JSON structure inside the Single Source of Truth (`seed_data.json`).
