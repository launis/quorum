# Fix Predefined Matrix Evaluations in TDAEngine

Investigating execution `exe_f4667bb499234119a59a4d590ef02c0a` revealed that Matrix evaluation steps (e.g., Fact Checker) produce **empty** matrix results. The `matrix_scoring_hook` finds zero atom matches because `TDAEngine` generates new UUIDs instead of using the predefined `tda_id` values from PromptBlock criteria.

## Architectural Context: "Context-Enriched Decompose-Verify"

Quorum's architecture is rooted in state-of-the-art 2025–2026 LLM research (e.g., Meta AI's System 2 Attention (S2A), DeepMind's SAFE, the FIRE framework from NAACL 2025, and CRAC studies). This research unambiguously demonstrates that evaluating raw text directly with an LLM leads to "Context Pollution"—the LLM gets confused by unresolved pronouns (anaphora) and irrelevant noise. Therefore, top-tier evaluation pipelines mandate a "Decompose-Verify" pattern: the source text is first **decomposed and enriched**, and only then are the claims **verified** against it.

The core of this bug fix is to preserve Quorum's existing architectural strength: the `TwoPassAtomizer` runs Phase 0 (Ontology) and Phase 1 (Anaphora Resolution) to create an **enriched context** where pronouns are resolved (e.g., "He" -> "John Doe"). The root cause of the bug is not the execution of these phases, but rather that `TDAEngine` attempts to evaluate *newly extracted, random atoms*, when it should be evaluating the **original predefined matrix questions** using the cleaned, enriched text as its *context*. This fix aligns Quorum perfectly with 2026 scientific best practices.

## Root Cause Analysis

1. **Orchestrator Strategy Routing**: The `dag_executor.py` routes `"reasoning"` and `"fast"` strategies to `TDAEngine`.
2. **Evaluation Target Mismatch**: `TDAEngine` currently evaluates the *newly extracted* atoms generated by `TwoPassAtomizer`. It ignores the predefined `shuffled_atoms` (the matrix questions).
3. **UUID Mismatch**: `matrix_scoring_hook` correlates results by matching `tda_id` against the PromptBlock's `tda_assertions`. Because TDA evaluates its own extracted atoms with new UUIDs, the hook finds zero matches → empty matrix.
4. **Scientific Context**: Bypassing Phase 0 and Phase 1 entirely would subject the matrix evaluation to "context pollution" (unresolved pronouns, noisy raw chat logs). We must use Phase 0+1 to generate an enriched context, but evaluate the *original* matrix atoms against it.

## Proposed Changes

### [MODIFY] [engine.py](file:///c:/src/quorum/backend_v2/models/dtos/engine.py)
To strictly enforce the **No Naked Dicts** rule without creating an architectural layer violation (Models importing from Hooks) or a Circular Import, we will **move** the `FlattenedAtom` model definition from `atom_flattening.py` into `engine.py` (or `dag_models.py`). 

```python
from pydantic import BaseModel, ConfigDict, Field

class FlattenedAtom(BaseModel):
    model_config = ConfigDict(strict=True, frozen=True, extra="ignore")
    atom_id: str
    question: str
    extraction_rule: str = ""
    anchor_target: str = ""
    is_inverse: bool = False

class EngineExecutionRequest(BaseModel):
    ...
    shuffled_atoms: list[FlattenedAtom] | None = Field(default=None, description="Predefined matrix assertions for TDA evaluation.")
```
By defining `FlattenedAtom` at the DTO layer, Pydantic V2 has runtime access for automatic coercion from `state_data` without needing `if TYPE_CHECKING:` hacks, and the dependency graph remains strictly unidirectional (Hooks depend on Models).

### [MODIFY] [llm.py](file:///c:/src/quorum/backend_v2/services/orchestrator/strategies/llm.py)
Pass the `shuffled_atoms` from `state_data` when the step is a matrix step. To enforce the **Fail-Fast Hydration Mandate** and **Zero-Duct-Tape Ban**, we MUST explicitly use dictionary key access `["shuffled_atoms"]` instead of `.get()`. This ensures that a missing key natively crashes via `KeyError` into a 500 error instead of silently passing `None` to Pydantic:

```python
engine_request = EngineExecutionRequest(
    ...
    shuffled_atoms=state_data["shuffled_atoms"] if is_matrix_step else None,
    ...
)
```

### [MODIFY] [tda_engine.py](file:///c:/src/quorum/backend_v2/services/orchestrator/engines/tda_engine.py)
Implement the **Context-Enriched Decompose-Verify Pipeline** while strictly preserving `AliasEngine` block tags and ensuring Prefix-Matching Cache Survival:

1. Execute **Phase 0** and **Phase 1** to generate `ontology` and `extracted_atoms`.
2. Construct a `full_context` string that combines BOTH the enriched facts AND the original `hydrated_text` (which contains the critical `[B0]`, `[B1]` block tags):
```python
enriched_claims = "\n".join(f"- {a.resolved_claim}" for a in extracted_atoms)
full_context = f"=== EXTRACTED FACTS (ONTOLOGY) ===\n{enriched_claims}\n\n=== SOURCE TEXT ===\n{hydrated_text}"
```
3. If `request.shuffled_atoms` is present, map them into `LinkedAtomGraph` nodes (preserving `tda_id`), and **skip** `SlidingWindowLinker` (because matrix assertions are independent).
4. Call `EnrichedDagExecutor.execute_graph()`, passing `full_context` as the `source_text`. By keeping the massive `full_context` at the absolute top of the prompt (`<context>`), we guarantee **O(1) Cache Survival** across the entire matrix chunk evaluation, bypassing standard token cost explosions.
5. Project via `ResultProjector.project()`.
