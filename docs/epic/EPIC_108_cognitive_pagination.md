# EPIC 108: Cognitive Pagination & Semantic Anchor Extraction (Atomizer NLP Optimization)

## 1. Objective
Eradicate physical string chunking during Atom Extraction (`TwoPassAtomizer.py`) to eliminate Context/Recall collapse, improve LLM comprehension (cognitive performance), and maximize Context Cache utilization.

## 2. Background & Problem Statement
Currently, the pipeline splits large documents physically (e.g., via `chunk.split("\n\n")`). This mechanical truncation destroys semantic integrity across chunk boundaries. When the LLM processes these disjointed chunks, it loses access to global context (such as pronouns or acronyms defined earlier in the document), leading to hallucinations or missing information during extraction. Furthermore, fragmented chunks prevent efficient utilization of a unified Context Cache.

*Note: This initiative was originally Phase 5 of EPIC 107 but was amputated and moved here to strictly isolate cognitive NLP algorithmic changes from structural Execution Pipeline orchestrator changes, enforcing the Zero-Behavioral Change rule.*

## 3. Architectural Constraints & Modernity Gates
* **Zero Legacy State Support Mandate**: Backward compatibility for past execution states or old database runs is STRICTLY PROHIBITED. No fallback logic, schema healing, or migration code is allowed for legacy runs. All development, execution, and verification MUST start from a completely clean slate by wiping the database and running `uv run python c:\src\quorum\backend_v2\seed\run_seed.py local`.

## 4. Execution Phases

### Phase 1: Zero-Chunking Cache Pagination & Attention Steering
* **Cross-Epic Delegation & Cache Lifecycles (Red-Team Fix)**: While the DAG Orchestrator manages global engine lifecycles, the Atomizer MUST manage its own isolated cache lifecycles for Phase 0 and Phase 1 due to varying system prompts. Inside `execute_phase_0` and `execute_phase_1`, the Atomizer MUST initialize a `CompiledPrompt` and call `LLMCachingService.pre_cache_document()` before the `asyncio.TaskGroup`, wrapping the TaskGroup in a `try...finally` block that explicitly calls `LLMCachingService.teardown_workflow_caches()` to prevent FinOps leaks.
* **New Settings Required** (Central Config Sovereignty — `backend_v2/settings.py`):
  * `max_concurrent_llm_steps: Annotated[int, Field(description="Max parallel LLM extractions within a TaskGroup")] = 3`
* **Architecture**:
  * **Semantic Anchor Pagination (Deterministic Boundary Calculation)**: Instead of physically splitting large documents, the Orchestrator MUST hydrate the text using `AliasEngine` (prefix="B") to create a single globally numbered block representation. The Orchestrator passes the globally hydrated `source_text` to the Atomizer (removing the chunk lists). Before opening the `asyncio.TaskGroup`, the Atomizer MUST deterministically calculate the logical chunk boundaries (e.g., slicing the hydrated text into extraction packets like Packet 1: [B0] to [B50]). These programmatically calculated boundaries are then passed into the parallel workers to drive their User Prompts.
  * **Attention Steering (Prefix Purity Mandate)**: The `TwoPassAtomizer` will spawn parallel extraction workers. **CRITICAL RULE**: To enforce Provider-Agnostic Caching (Static-First Topology), the worker payload MUST utilize the orchestrator's `CompiledPrompt`. The full `hydrated_text` MUST be placed inside a `<source_data>` tag within the static `user` message. The specific packet boundary instruction (e.g., "Extract atoms ONLY from [B0] to [B50]") MUST be injected dynamically as a user message wrapped strictly inside `<execution_parameters>` at the absolute end of the sequence. Do NOT strip `<source_data>`.
  * **Bounded Concurrency & DLQ Routing**: The parallel extraction workers MUST be orchestrated within an `asyncio.TaskGroup` constrained by a native `asyncio.Semaphore(settings.max_concurrent_llm_steps)` to prevent HTTP 429 Thundering Herd failures. Furthermore, workers MUST trap unhandled exceptions and append a strictly typed Dead Letter Queue (DLQ) output state to a shared result list instantiated outside the TaskGroup. An unhandled exception in a single extraction worker MUST NOT be allowed to bubble up and cancel the entire `TaskGroup` (which would orphan all other executing parallel extractions).
  * **Contextual Preservation**: Because the entire document is resident in the cache, the LLM retains access to the global context (e.g., resolving pronouns or acronyms defined on page 1, even if the worker is assigned to extract atoms from page 15). This prevents the hallucinations caused by arbitrary line/paragraph chunking mid-dialogue.
  * **Chronological Preservation Mandate (Python-Injected Metadata)**: Because parallel extraction workers complete non-deterministically, the extracted output MUST strictly enforce a `source_sequence_index: int` field. **CRITICAL RULE**: Do NOT ask the LLM to generate this index in its Structured Output, as it introduces unnecessary hallucination risks. The Python worker function MUST programmatically inject its known sequence index into the resulting Pydantic DTOs immediately after successful LLM generation. To strictly enforce the Zero-Compromise Pledge, this field MUST NOT have a default value (no `= None` or `= 0`). Furthermore, introducing this required field means you MUST explicitly update all mock instantiations in the test suite (e.g., `backend_v2/tests/`) to prevent cascading `ValidationError` crashes. The DAG Orchestrator MUST use this index to explicitly `.sort()` the aggregated list of atoms before proceeding.
  * **Post-Generation Boundary Validation (Fail-Fast)**: Because the entire document is present in the cache, the LLM may suffer instruction drift and extract atoms outside its strictly assigned range. A programmatic Python validation hook MUST be executed immediately after the worker returns the atoms. Any atom referencing a source block outside the worker's strict bounds MUST trigger a Fail-Fast `ValueError`. This ensures the error is caught by the **Tenacity `@retry` loop** (forcing the chunk extraction to be retried) rather than silently dropping corrupt data.
