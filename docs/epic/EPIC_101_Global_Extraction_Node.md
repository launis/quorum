# EPIC 101: RAG Pre-Flight Pipeline & Deterministic Anchoring
**Status**: APPROVED  
**Targeted Subsystem**: Backend Macro-Orchestrator (`backend_v2/services/orchestrator/`), RAG Pipeline

## 1. Problem Statement & Root Cause
During the testing of the Epic 100 DAG execution, a catastrophic architectural bottleneck was discovered. The new Micro-DAG extraction logic (`TwoPassAtomizer` and `SlidingWindowLinker` - the "väitteiden haut") was correctly implemented, but it was executed independently for *each* of the 13 UI steps. 

Because each step splits the document into 15 chunks, the orchestrator triggers 195 heavy LLM calls simultaneously. This instantly triggers `429 Resource Exhausted` rate limits on Vertex AI and stretches a 20-minute execution into a 4+ hour crawl. 

## 2. Architectural Objectives (The RAG Pipeline)
To achieve instantaneous sub-second evaluation for the 13 UI steps **without altering the UI architecture**, we must extract the heavy cognitive lifting into a dedicated RAG (Retrieval-Augmented Generation) Pipeline that runs invisibly "under the hood".

1. **RAG Pre-Flight Pipeline**: We will create an invisible "Pre-Flight" RAG phase inside the Macro-Orchestrator (`DAGExecutor`). Before the UI workflow steps even begin, this pipeline will autonomously aggregate all Matrix Block rules from the 13 steps. It will execute the `TwoPassAtomizer` Map-Reduce over the document exactly **ONCE** and store the extracted facts (`DraftAtomList`) into the `ExecutionRecord.context_variables` (The "Blackboard").
2. **Virtual Step Injection (Live UI)**: To ensure the UI is "alive" during the 2-minute RAG extraction without polluting the admin configuration, the `DAGExecutor` will automatically inject a Virtual Step (e.g., "Asiakirjan Esianalyysi") into the runtime state. It will emit `TraceEvent(event_type="progress")` against this virtual step. (Note: `state.py` must be updated to include `"progress"` in the `TraceEvent.event_type` Literal). The user sees a dedicated loading card, while the actual defined 13 steps remain `PENDING`.
3. **Pre-Hydrated Synthesis Strategy**: We will create a new strategy for all subsequent UI steps. Instead of running their own heavy Map-Reduce chunking (which caused the 429 errors), these steps will read the pre-computed RAG Blackboard. They will then make EXACTLY ONE fast LLM call per step. This single call is fed the pre-extracted facts and the step's Matrix Block, allowing the AI to write rich analytical and coaching texts without re-reading the entire document.

## 2.5 The "Dual-Input" Synthesis Model (The Map & The Encyclopedia)
To ensure the UI's deep analytical capabilities (e.g., Toulmin's Model, "Missing Context" detection, BARS scales) are preserved, the Pre-Hydrated Synthesis Strategy uses a **Dual-Input Context** approach:
1. **The Blueprint**: `PromptCompiler` imports the step's Matrix Block rules exactly as defined in the UI. No UI logic is lost.
2. **The Map (`GlobalAtomBlackboard`)**: The AI is fed the pre-extracted facts (atoms). It does not need to scan the document, it just reads this "map" of claims.
3. **The Encyclopedia (Context Cache)**: The raw, 50-page source document (`$inputs.product_text`) is still loaded invisibly into the Vertex AI Context Cache. This acts as a free, instantaneous "encyclopedia" the AI can glance at if it needs to find "missing context" or deep background for its coaching tips.

**Mathematical Impact:**
- **Old Architecture:** 15 map-reduce chunks * 13 steps = **195 concurrent calls**. This caused instantaneous 429 Rate Limit (Pacing Lock) crashes.
- **Epic 101 Architecture:** 15 chunks (Pre-Flight) + 13 steps (Synthesis) = **28 controlled calls**. The bottleneck is completely eliminated while maintaining 100% of the cognitive depth.

## 3. High-Level Implementation Phases

### Phase 1: RAG Pre-Flight Pipeline & Virtual Step Injection
- **Component**: `backend_v2/services/orchestrator/dag_executor.py` and `backend_v2/models/state.py`
- **Cross-Boundary Note**: Adding `"progress"` to `TraceEvent.event_type` Literal in `backend_v2/models/state.py` is a backend-only change because the Flutter client consumes the projection (`step_states`), not the raw `TraceEvent`. No Flutter Freezed update is required for `TraceEvent`.
- **Logic**: Implement the RAG Pre-Flight hook before the step iteration loop. It must:
  1. **Pre-Condition Scan (Conditionality Optimization)**: Before performing any operations, `DAGExecutor` MUST scan `workflow.steps`. If no step has `engine_override == EngineOverrideStrategy.PRE_HYDRATED_SYNTHESIS`, the entire Pre-Flight phase MUST be skipped to avoid wasting tokens on non-analytical workflows.
  2. Inject an ephemeral `ExecutionStepState` with a dynamically generated opaque ID (e.g., `f"stp_{uuid.uuid4().hex[:16]}"`) with status `RUNNING`. **CRITICAL ARCHITECTURE MANDATE (RED-TEAM FIX)**: The original plan instructed using `workflow.model_copy()` to inject a Virtual `StepRule` into `workflow.steps`. This is STRICTLY BANNED. The `workflow.steps` array controls the `DAGExecutor` iteration loop; inserting non-existent steps there will cause fatal scheduling errors (`ConfigurationError`) when the engine tries to find dependencies for them. To achieve UI rendering without crashing the engine, the Virtual Step is ONLY injected into `exec_record.step_states` (the output payload sent to the client). The engine loop remains pure and untouched.
  3. Inspect the `workflow` object to collect all `expected_inputs`. For EACH input file (e.g., `product_text`, `chat_log`), chunk it independently using the existing `ChunkingService` and run `TwoPassAtomizer` per file. **CRITICAL ARCHITECTURE MANDATE (RED-TEAM FIX)**: The original Epic draft instructed running `SlidingWindowLinker` here. That is strictly BANNED. Because `GlobalAtomBlackboard` stores unlinked `DraftAtomList` objects, generating topological causal edges is a waste of LLM tokens and latency. The Linker MUST be completely omitted from the pre-flight phase. This Atomization MUST occur exclusively via `LLMTaskExecutor.execute_structured_task()` to eradicate syntactic self-healing regex loops. The LLM client MUST be resolved via `LLMClient.from_strategy("fast", repo)` (where `"fast"` is an existing strategy defined in the `seed_data.json` database) for cost-efficient parallel chunking.
  4. Execute using `asyncio.TaskGroup` constrained by `asyncio.Semaphore(settings.max_concurrent_llm_steps)`. The use of `asyncio.gather` is STRICTLY BANNED to prevent zombie tasks (straggler issue). Furthermore, if a worker node crashes in a TaskGroup, the entire DAG execution is cancelled. We must enforce Dead Letter Queue (DLQ) routing (`dlq_arq_fallback_routing`) instead of raising naked exceptions to safely isolate task failures.
  5. Emit `progress` TraceEvents tied to the virtual step dynamically during the Map-Reduce loop to keep the SSE connection alive.
  6. The extracted atoms MUST be grouped by their source file using a new strict Pydantic model: `class GlobalAtomBlackboard(BaseModel): atoms_by_input: dict[str, DraftAtomList]`. This model MUST be defined in `backend_v2/models/domain/blackboard.py` (per `strict_model_location` mandate). The `DraftAtomList` and `DraftExtractedAtom` models currently defined in `two_pass_atomizer.py` MUST be migrated to `backend_v2/models/domain/` as the SSOT during implementation. This model MUST enforce `model_config = ConfigDict(frozen=True, extra="forbid", strict=True)` to prevent in-place mutation violations. Project this Pydantic model into `context_variables["global_atoms"]` via `.model_dump(mode="json")`. **NOTE**: Cloud Storage offload via `context_variables_storage_path` is completely removed from the scope of this Epic and deferred. Typical RAG atom payloads (~50-200KB) are well within TinyDB limits.
  7. Mark the Virtual Step as `ExecutionStatus.PASSED`.

### Phase 2: Pre-Hydrated Synthesis Strategy (The Fast Path)
- **Component**: `backend_v2/services/orchestrator/strategies/pre_hydrated_synthesis.py`
- **Logic**: Implement a strategy that replaces the heavy Map-Reduce `LLMExecutionStrategy` for all analytical steps while preserving 100% of the UI's prompt configuration. It must:
  1. **Hydrate Facts & Alias Isolation**: Read the step's specific input mappings (e.g., only `$inputs.product_text`). **CRITICAL ARCHITECTURE MANDATE (RED-TEAM FIX)**: The `DAGExecutor` does not natively pass `context_variables` down to `NodeExecutor`. You MUST structurally update the `StrategyContext` model to explicitly include `context_variables` so the data pipeline is complete. Once wired, hydrate the Blackboard explicitly using `GlobalAtomBlackboard.model_validate(context_variables["global_atoms"])`. Extract ONLY the corresponding `DraftAtomList`s for the mapped files. **CRITICAL**: Before injecting these atoms into the LLM prompt, you MUST pass them through the `AliasEngine` (per `ki_opaque_id_hydration.md`) to convert their long UUIDs into short semantic aliases (e.g., `a0`, `a1`) to prevent Attention Drift. If the LLM is expected to reference atoms in a JSON structure, use the same engine to hydrate the aliases back to UUIDs post-execution. This ensures steps only receive facts from the files selected in the UI without causing token bloat.
  2. **Preserve Prompt Logic & XML Structural Sovereignty**: Use the existing `PromptCompiler` to perfectly preserve the step's Matrix rules (BARS scales, Toulmin models, XAI requirements) exactly as defined in the UI. Developers are STRICTLY BANNED from injecting raw, unstructured f-strings. The compiled prompt MUST be deterministically fenced within immutable XML boundaries (e.g., `<system_directive>`, `<user_payload>`) to prevent injection leakage and cache-busting.
  3. **Dual-Input Context (Ephemeral Caching Topology)**: Formulate a single LLM prompt that passes the raw source files (e.g., `$inputs.product_text`) into the Vertex AI Context Cache. To prevent cache-busting and FinOps cost explosions, you MUST enforce the Ephemeral Caching Topology: The System Prompt must be 100% static, and the `global_atoms` working memory MUST be injected at the absolute end inside a dynamic `<user_payload>`.
  4. **Single-Call Synthesis**: Execute EXACTLY ONE LLM call via `LLMTaskExecutor.execute_structured_task()` (routed through `LLMClient.from_strategy()` using the step's native `model_strategy`, which corresponds to existing values in the `seed_data.json` database like `"synthesis"`, `"deep"`, or `"strict"`) to generate the creative SDUI DTOs (e.g., CoachingCard, InsightCard) based on those verified facts and rules.

## 4. Quality Gates & Red-Teaming (System 2 Safeguards)

> **Architectural Philosophy: The Nuclear Power Plant vs. The Self-Driving Car**
> Modern AI systems increasingly resemble self-driving cars: highly autonomous, proactively self-correcting, and adaptable to their environments. Quorum, however, is intentionally designed as a **Nuclear Power Plant Control System**. It is absolutely mechanical, extremely secure, and prefers to crash (Fail-Fast) rather than make a silent mistake or hallucinate. While this purist rigidity temporarily suffocates unbounded "agentic" intelligence, it is **the only viable and safe approach for initial Enterprise deployment**. We sacrifice proactive autonomy for zero-tolerance error handling.

- **UI Fallback Guarantee (Virtual Injection Risk)**: To mitigate the risk of Virtual Step injection crashing the client, the Flutter SDUI `AppErrorBoundary` MUST be updated to gracefully render a `SduiLoadingSkeleton` for any unrecognized Virtual Step IDs, rather than throwing a hard exception.
- **TaskGroup Cascade Isolation (Error Management Risk)**: Because `asyncio.TaskGroup` inherently cancels all sibling tasks if a single coroutine raises an exception, the `TwoPassAtomizer` worker MUST wrap its entire internal chunk execution in a resilient `try-except` block. Upon a transient error (e.g. 503/429), it MUST retry per `ki_transient_error_resilience`. Upon a structural failure or exhausted retries, it MUST route the error payload to the DLQ (`dlq_arq_fallback_routing`) by returning a DLQ sentinel object (e.g., `DraftAtomList(atoms=[], dlq_status="FAILED/DLQ")` with proper metadata) rather than a silently empty list. The Blackboard aggregation phase MUST check for DLQ markers and emit observability events. **Pydantic Strictness Exception**: Because the models enforce `extra="forbid"`, the `DraftAtomList` model MUST explicitly define `dlq_status: str | None = Field(default=None)` as a valid optional field to prevent a `ValidationError` crash when the sentinel is instantiated.
- **Blackboard Anti-Corruption Layer (Data Model Strictness Risk)**: Because `GlobalAtomBlackboard` is `frozen=True` and `extra="forbid"`, any malformed JSON from the LLM will cause a catastrophic Fail-Fast crash during `model_validate()`. To prepare for this, the `TwoPassAtomizer` MUST implement a strict validation boundary that sanitizes and drops individually corrupted `DraftExtractedAtom` instances *before* they are aggregated into the Blackboard, ensuring partial success is preserved. **Crucially (Dual-Reporting Mandate)**: Silent data loss is strictly banned. Every single dropped atom MUST emit a structured `logger.warning("corrupted_atom_dropped", extra={"raw_payload": ...})` event so schema degradation is tracked in observability platforms (Sentry/Datadog) without triggering false-positive incident pages for graceful recoveries.
- **Alias Hallucination Resilience (Reverse Hydration Risk)**: During Phase 2, when the `AliasEngine` converts LLM-generated aliases (e.g., `a99`) back to UUIDs, there is a statistical risk of LLM alias hallucination (referencing an alias that was not in the prompt). The reverse mapping MUST be strictly Fail-Fast at the entity level: if an invalid alias is referenced, the engine MUST immediately drop the invalid reference. **CRITICAL ARCHITECTURE MANDATE (RED-TEAM FIX)**: The existing `AliasEngine.hydrate_dict_list()` is broken because it does not drop invalid aliases, which will cause Pydantic to crash. The developer MUST create a completely new method `hydrate_and_filter_aliases` that recursively checks and explicitly drops (`None`) hallucinated aliases from BOTH lists and individual scalar string fields. To comply with the Dual-Reporting Mandate, it MUST log a structured `logger.warning("hallucinated_alias_dropped")` so that model degradation is traceable, preventing a full `KeyError` crash while maintaining strict topological integrity.
- **Payload Bloat Risk (Atom Ceiling)**: To protect TinyDB's synchronous I/O and prevent LLM context window bloat during the Synthesis phase, the `GlobalAtomBlackboard` MUST enforce a strict Fail-Fast ceiling. If a single document extraction yields over the allowed limit of atoms, the validation MUST fail. To comply with Global Config Sovereignty, this limit MUST NOT be a magic number in the Pydantic model or an Enum. It MUST be defined in `settings.py` (e.g., `settings.max_extracted_atoms_per_document = 500`) and validated against this setting.
- **Cache-Busting Prevention (Topology Verification)**: To guarantee the Ephemeral Caching Topology, the backend MUST implement a structural unit test for the `PromptCompiler` that compares the `System Message` hash between two different executions of the same matrix rule. If the hash differs, dynamic data has leaked into the static block, and the test MUST fail. The dynamic `global_atoms` MUST strictly be injected exclusively into the trailing `<user_payload>` block.
- **Quote Normalization Strategy (Physical Anchoring Risk)**: While `str.find` is strict, minor discrepancies in LLM whitespace generation (e.g., `\n` vs `\r\n`, or double spaces) can cause false-negative hallucination rejections. Instead of building a new normalizer, the system MUST leverage the existing `AnchorValidationService.normalize_text_with_mapping()` utility. This must be applied to BOTH the source text and the generated quote *before* executing the `str.find` validation, ensuring deterministic anchoring while preserving resilience against minor encoding differences.
- **State Sovereignty**: The RAG Pipeline must adhere strictly to `ki_dag_engine_dto_projection_rules.md`. It must NOT return raw Python dictionaries.
- **Fail-Fast Hydration**: If `context_variables["global_atoms"]` is missing, the `PreHydratedSynthesisStrategy` must log a structured `logger.error` with execution context (Dual-Reporting Mandate) and then crash immediately with a `DependencyError`.
- **Single-Call Mandate (Future-Proof Reflection)**: The `PreHydratedSynthesisStrategy` MUST be hardcoded to never loop or map-reduce. It must guarantee exactly 1 LLM request per step. Cognitive depth and reflection MUST be delegated to native provider reasoning models (e.g., via `model_strategy="reasoning"`) or explicit multi-step DAG configurations, rather than building brittle, hidden multi-call reflection loops in Python.
- **DAG-Level Multi-Agent Reflection (No Hidden Loops)**: Because the `seed_data.json` configuration natively supports independent, observable reviewer nodes (e.g., 'Kriittinen Tuomari', 'Kriittinen Auditoija'), any requirement for human-like proofreading or multi-pass debate MUST be modeled explicitly as sequential UI steps in the DAG. Implementing invisible reflection loops inside backend Python strategies subverts user transparency and is strictly banned.
- **LLM FinOps & Routing (Cascading vs Bo3)**: The `PreHydratedSynthesisStrategy` MUST default to highly cost-efficient Cascading Routing instead of brute-force Best-of-Three (Bo3). **Architectural Override**: This explicitly supersedes the `ki_tda_best_of_three_flash.md` mandate for Synthesis steps. High-entropy evaluation is shifted from Python-level Bo3 loops to API-level latent reasoning (`model_strategy="reasoning"`). Python-level Bo3 MUST be strictly reserved for terminal "Final Verdict" nodes. Intermediate extraction and synthesis nodes must use the cheapest capable model strategy (e.g., `"fast"`) and escalate to `"reasoning"` only dynamically (e.g., upon Pydantic validation failures) or when statically configured for critical steps in `seed_data.json`.
- **Deferred Multimodal Preservation (Spatial RAG Limitations)**: The Phase 1 design currently relies on text-based chunking. While flat-text OCR loses layout semantics, forcing native PDF endpoints (VLM) contradicts the string-based `ChunkingService` required for map-reduce processing. Therefore, native PDF spatial RAG is DEFERRED to a future Epic. Phase 1 MUST use the text-based chunking approach, acknowledging that complex tables and layout semantics are a known limitation of the current extraction pipeline.
- **Physical Anchoring & Null Hypothesis**: The extraction pipeline MUST enforce strict O(N) physical anchoring (`str.find`) for all quotes. Fuzzy matching is strictly banned. To support facts deduced purely through logic, the AI must use the `is_logical_deduction == True` flag to intentionally force the quote to `None`.
- **Tripartite Configuration Architecture**: All configuration parameters (such as `max_concurrent_llm_steps` and `context_variables_offload_threshold_bytes`) MUST be explicitly segregated and enforced via the explicit Tripartite structure (`enums.py`, `settings.py`, `DTO blueprints`). Do not hardcode magic numbers.
- **Rogue SDK Ban**: The `PreHydratedSynthesisStrategy` MUST NOT import provider SDKs directly. All model calls MUST be routed through the mandated `LLMClient.from_strategy()` abstraction to maintain Model Agnosticism.
