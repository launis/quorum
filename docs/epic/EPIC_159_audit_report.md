## 1. Executive Summary & Zero-Behavioral-Change Gate

`@[docs/epic/EPIC_159_DYNAMIC_MCP_ARCHITECTURE.md]` transitions Quorum V2 from static, hardcoded Python tool wrappers (`tavily.py`, `wikipedia.py`, `tavily_search_client.py`, `wikipedia_client.py`) and permissive `dict[str, JsonValue]` tool schemas to a protocol-agnostic Model Context Protocol (MCP 2025-03-26) architecture supporting Streamable HTTP and HTTP+SSE transports, recursive Pydantic V2 JSON Schema AST validation (`MCPToolSchemaPropertyDTO` and `MCPToolInputSchemaDTO`), runtime `pydantic.create_model` schema compilation, collision-free `{gateway_slug}__{tool_id}` namespace routing, SSRF/DNS-rebinding protection (`MCPUrlValidator`), and live tool introspection in Quorum Studio (`client_app_v2`).

- **Zero-Behavioral-Change Gate Classification**: EPIC 159 is a **Feature & Architecture Modernization Epic**. To prevent mixing pre-existing technical debt remediation with new feature logic, **Phase 1.1** is strictly isolated as a **Zero-Behavioral-Change Pre-Implementation Technical Debt Cleanup Gate** resolving all 64 Python AST/technical debt findings and 18 Flutter Theme Sovereignty findings before new recursive DTOs and dynamic MCP transport logic are introduced in Phases 1.2 through 4.

## 5. Red-Team Falsification & Concrete Failure Modes Hardened in Epic

### Failure Mode 1: Cross-Language Enum Parity Violation on `ToolCapability` (`no_raw_string_enum_mappings` & `cross_language_enum_parity`)
- **Root Cause**: `ToolCapability(StrEnum)` exists in `@[backend_v2/models/enums.py]` (`SEARCH = "search"`, `DOCUMENT_READER = "document_reader"`, `ACTION = "action"`, `GENERAL = "general"`), and `AllowedMCPTool.capability` is typed as `ToolCapability` in Python. However, in `@[client_app_v2/lib/features/studio/models/mcp_gateway.dart]`, `AllowedMcpTool.capability` is typed as a raw `String` (`@Default('search') String capability`), `ToolCapability` is missing from `@[client_app_v2/lib/core/models/enums.dart]` and `@[backend_v2/tests/unit/test_enum_parity.py]`, and Phase 4.2 of the Epic originally proposed `DropdownButtonFormField<String>` with hardcoded string values in `@[client_app_v2/lib/features/studio/views/mcp_gateway_view.dart]`.
- **Architectural Justification**: `@[.agents/rules/02_flutter_desktop.md]` (`no_raw_string_enum_mappings` and `cross_language_enum_parity`) strictly prohibits raw string enum fields and `DropdownButtonFormField<String>` for fixed backend `StrEnum` taxonomies. Adding `@JsonEnum() enum ToolCapability` (`@JsonValue('search') search`, `@JsonValue('document_reader') documentReader`, `@JsonValue('action') action`, `@JsonValue('general') general`) in `@[client_app_v2/lib/core/models/enums.dart]`, typing `AllowedMcpTool.capability` as `@Default(ToolCapability.search) ToolCapability capability`, asserting 1:1 parity in `@[backend_v2/tests/unit/test_enum_parity.py]`, and binding `DropdownButtonFormField<ToolCapability>` in `McpGatewayView` guarantees compile-time and serialization parity across Python and Dart.

### Failure Mode 2: Streamable HTTP & SSE `text/event-stream` Framing vs. Raw `model_validate_json(response.text)` Crash in `GenericMCPClient`
- **Root Cause**: Phase 2.2 originally instructed `GenericMCPClient` to validate `tools/list` and `tools/call` responses directly via `MCPJsonRpcResponseDTO.model_validate_json(response.text)`. Under the MCP 2025-03-26 Streamable HTTP and HTTP+SSE specifications, compliant MCP servers may return `Content-Type: text/event-stream` containing SSE-framed lines (`event: message`, `data: {"jsonrpc":"2.0",...}`), keep-alive comments (`: ping`), and asynchronous server notifications lacking a request `id`. Passing an SSE-framed HTTP body directly to `model_validate_json(response.text)` causes an immediate JSON syntax crash.
- **Architectural Justification**: Hardening `GenericMCPClient` in Section 2.5 and Phase 2.2 with a deterministic dual wire-framing parser that inspects `Content-Type` (`application/json` direct validation vs. `text/event-stream` SSE `data:` frame extraction and `request.id` correlation ignoring keep-alive comments and server notifications) ensures 100% protocol compliance across both `STREAMABLE_HTTP` and `SSE` gateways while still validating all payloads exclusively through `MCPJsonRpcResponseDTO.model_validate_json`.

### Failure Mode 3: Bijective Namespace Splitting (`split("__", 1)`) & Non-Empty `tool_id` Constraint
- **Root Cause**: `SystemConfigMCPGateways.slug` is restricted to single underscores (`r"^[a-z0-9]+(?:_[a-z0-9]+)*$"`), making the first `"__"` in `{gateway_slug}__{tool_id}` the exact boundary between gateway slug and tool ID. However, an external MCP server's `tool_id` may itself contain `"__"`, or an empty `tool_id` could be constructed. Calling `.split("__")` without `maxsplit=1` would reject or corrupt external tool IDs containing double underscores.
- **Architectural Justification**: Enforcing `min_length=1` on `AllowedMCPTool.tool_id` in `@[backend_v2/models/domain/system_config.py]` (Phase 1.2) and specifying `namespaced_alias.split("__", 1)` in `AliasRegistry.parse_namespaced_tool_alias` (Phase 3.2) guarantees a mathematically bijective split between the single-underscore `gateway_slug` and any non-empty external `tool_id`.

### Failure Mode 4: Desktop Pro Tool UX & Horizontal Overflow Immunity in `McpGatewayView` (`@[ki_desktop_pro_tool_studio_ux.md]`)
- **Root Cause**: Inspection of `@[client_app_v2/lib/features/studio/views/mcp_gateway_view.dart]` revealed that the root form `ListView` lacks `ConstrainedBox(constraints: const BoxConstraints(maxWidth: 1200))` wide-canvas containment, the section header `Row` at line 253 places `Text(l10n.allowedMcpToolsTitle)` beside `FilledButton.icon` without `Expanded` wrapping, and the newly introduced parameter schema preview table in Phase 4.2 requires horizontal scroll and cell width constraints to avoid `RenderFlex overflowed` exceptions on long JSON Schema descriptions.
- **Architectural Justification**: Explicitly mandating `Center -> ConstrainedBox(constraints: const BoxConstraints(maxWidth: 1200))`, `Expanded(child: Text(..., overflow: TextOverflow.ellipsis))` in header rows, and horizontal `SingleChildScrollView(scrollDirection: Axis.horizontal)` + `ConstrainedBox(constraints: const BoxConstraints(maxWidth: 350))` on `DataTable` description cells in Phase 4.2 enforces `@[.agents/rules/02_flutter_desktop.md]` (`wide_and_ultrawide_canvas_containment_mandate` and `universal_horizontal_overflow_immunity_mandate`).

### Failure Mode 5: Atomic Phase 3.2 Test Migration for `@[backend_v2/tests/unit/services/mcp/test_mcp_tool_loop.py]`
- **Root Cause**: `@[backend_v2/tests/unit/services/mcp/test_mcp_tool_loop.py]` patches `backend_v2.services.mcp.mcp_tool_loop.DISPATCHER.execute_tool` and passes un-namespaced tool IDs (`"mcp_tavily_search"`, `"mcp_wikipedia_read"`). While listed in Section 4.2, it was omitted from the Phase 3.2 target header where `DISPATCHER` is removed from `@[backend_v2/services/mcp/mcp_tool_loop.py]`.
- **Architectural Justification**: Adding `[MODIFY] @[backend_v2/tests/unit/services/mcp/test_mcp_tool_loop.py]` directly to Section 1.4, Section 2.5 (Row 4), and Phase 3.2 ensures atomic test migration alongside `mcp_tool_loop.py` so the Phase 3.2 quality gate passes without broken module attribute patches.
