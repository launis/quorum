## 1. Goal Description & Background (Objective & Problem Statement)

### Business Objective

Fix a critical production bug where Matrix evaluation steps (e.g., Fact Checker) produce **empty** matrix results. The `matrix_scoring_hook` finds zero atom matches because `TDAEngine` generates new UUIDs instead of using the predefined `tda_id` values from PromptBlock criteria.

### Problem Statement

Investigation of execution `exe_f4667bb499234119a59a4d590ef02c0a` revealed that the `matrix_scoring_hook` correlates results by matching `tda_id` against the PromptBlock's `tda_assertions`. Because TDA evaluates its own extracted atoms with new UUIDs, the hook finds zero matches → **empty matrix**.

### Architectural Context: "Context-Enriched Decompose-Verify"

Quorum's architecture is rooted in state-of-the-art 2025–2026 LLM research (e.g., Meta AI's System 2 Attention (S2A), DeepMind's SAFE, the FIRE framework from NAACL 2025, and CRAC studies). This research unambiguously demonstrates that evaluating raw text directly with an LLM leads to "Context Pollution" — the LLM gets confused by unresolved pronouns (anaphora) and irrelevant noise. Therefore, top-tier evaluation pipelines mandate a "Decompose-Verify" pattern: the source text is first **decomposed and enriched**, and only then are the claims **verified** against it.

The core of this bug fix is to preserve Quorum's existing architectural strength: the `TwoPassAtomizer` runs Phase 0 (Ontology) and Phase 1 (Anaphora Resolution) to create an **enriched context** where pronouns are resolved (e.g., "He" -> "John Doe"). The root cause of the bug is not the execution of these phases, but rather that `TDAEngine` attempts to evaluate *newly extracted, random atoms*, when it should be evaluating the **original predefined matrix questions** using the cleaned, enriched text as its *context*. This fix aligns Quorum perfectly with 2026 scientific best practices.

### Root Cause Analysis

1. **Orchestrator Strategy Routing**: The `dag_executor.py` routes `"reasoning"` and `"fast"` strategies to `TDAEngine`.
2. **Evaluation Target Mismatch**: `TDAEngine` currently evaluates the *newly extracted* atoms generated by `TwoPassAtomizer`. It ignores the predefined `shuffled_atoms` (the matrix questions).
3. **UUID Mismatch**: `matrix_scoring_hook` correlates results by matching `tda_id` against the PromptBlock's `tda_assertions`. Because TDA evaluates its own extracted atoms with new UUIDs, the hook finds zero matches → empty matrix.
4. **Scientific Context**: Bypassing Phase 0 and Phase 1 entirely would subject the matrix evaluation to "context pollution" (unresolved pronouns, noisy raw chat logs). We must use Phase 0+1 to generate an enriched context, but evaluate the *original* matrix atoms against it.

> This change mutates the DAG Orchestrator ecosystem. Per rule `orchestrator_god_object_fragility`, explicit "PERMISSION GRANTED to mutate DAG Orchestrator ecosystem" is required before execution.

### Phase 1: Backend Domain Models & Service Engine Hardening

#### [MODIFY] [engine.py](file:///c:/src/quorum/backend_v2/models/dtos/engine.py)

Move `FlattenedAtom` model definition into the DTO layer to strictly enforce the **No Naked Dicts** rule without creating an architectural layer violation (Models importing from Hooks) or a Circular Import.

```python
from typing import Annotated
from pydantic import BaseModel, ConfigDict, Field

class FlattenedAtom(BaseModel):
    # duck_typing_token_shield_exception: Internal Data Projection Model — extra="ignore"
    # is permitted to allow safe deserialization from hook state_delta which may contain
    # transient metadata keys outside this schema's concern.
    model_config = ConfigDict(strict=True, frozen=True, extra="ignore")
    atom_id: Annotated[str, Field(description="Opaque hashed ID for the extracted atom.")]
    question: Annotated[str, Field(description="The text content evaluated blindly.")]
    extraction_rule: Annotated[str, Field(default="", description="The specific validation rule.")] = ""
    anchor_target: Annotated[str, Field(default="", description="Semantic bounding box target.")] = ""
    is_inverse: Annotated[bool, Field(default=False, description="True if this is an inverse assertion.")] = False

class EngineExecutionRequest(BaseModel):
    ...
    shuffled_atoms: Annotated[list[FlattenedAtom] | None, Field(default=None, description="Predefined matrix assertions for TDA evaluation.")] = None
```

By defining `FlattenedAtom` at the DTO layer, Pydantic V2 has runtime access for automatic coercion from `state_data` without needing `if TYPE_CHECKING:` hacks, and the dependency graph remains strictly unidirectional (Hooks depend on Models).
