# IMPLEMENTATION PLAN: Task Assignment, Task Brief CRUD+Clone & Direct Portal End-to-End Hardening (Findings A–E)

## 1. Objective & Architectural Background

Cold-testing and System 2 red-teaming of the 6-stage Time-Bound Task Assignment and Direct Task Portal (`/task/:token`) workflow across `@[backend_v2/services/execution/assignment_service.py]`, `@[backend_v2/services/auth/email_service.py]`, `@[backend_v2/services/studio/prompt_block_service.py]`, `@[client_app_v2/lib/features/execution/views/task_assignment_portal_view.dart]`, `@[client_app_v2/lib/features/execution/views/new_execution_view.dart]`, and `@[client_app_v2/lib/features/settings/presentation/organization_iam_settings_view.dart]` identified five functional requirements (**Findings A, B, C, D, and E**) together with nine cross-layer contract and runtime failure traps that must be resolved in a single normalized architecture:

1. **Finding C — Canonical Resend REST Payload & Escaped HTML CTA Composition (`@[backend_v2/services/auth/email_service.py#L49-L327]`):**
   - **Root Cause:** `TransactionalEmailItemDTO` isolates `action_url` inside `SecretStr` to prevent cleartext token leakage in logs (`QGR033`). However, `EmailService._send_single_http_item` sends `html_body` without embedding `item.action_url.get_secret_value()` into a clickable `<a href="...">` button, omits Resend's required `"html"` field, and sends non-standard root keys (`"html_body"`, `"action_url"`, `"category"`, `"entity_id"`, `"recipient_name"`, `"locale"`) that strict Resend `POST /emails` Zod validation rejects with HTTP 400/422.
   - **Architectural Justification:** Add `EmailService._compose_transactional_html(html_body: str, action_url: SecretStr) -> str` escaping `raw_url` via `html.escape(raw_url, quote=True)` and appending an English HTML CTA button (`Open Quorum Portal`) plus copyable fallback link when the URL is not already present, and standardize `_send_single_http_item` on the single canonical Resend schema (`from`, `to`, `subject`, `html`, and `tags` containing `category`, `entity_id`, and `locale`) with zero legacy duplicate `"html_body"` or raw `"action_url"` root keys (`universal_ssot_and_normalization_mandate`).

2. **Finding E — Normalized Task Brief (`PromptBlockCategory.TASK_DEFINITION`) CRUD + Clone (`copy`) & First-Class Foreign Key Relation (`@[backend_v2/services/studio/prompt_block_service.py#L188-L242]`, `@[backend_v2/database/migrations/001_pg19_uuidv7_schema.sql#L400-L433]`, `@[backend_v2/models/domain/execution.py#L541-L672]`, `@[backend_v2/models/auth.py#L1154-L1215]`):**
   - **Root Cause:** Coaches (`ADMIN` and `ROOT`) require a 5-operation CRUD + Clone (`copy`) lifecycle for reusable Task Brief / Case Description prompt blocks (`PromptBlockCategory.TASK_DEFINITION`). Attempting to pass Task Brief fields (`task_brief_id`, `task_brief_title`, `task_brief_text`, `task_brief_url`) through `lockedInputs.dynamicInputs` pollutes `ExecutionRecord.raw_inputs.dynamic_inputs` and `source_identity_manifest` and triggers `SmartIngressResolver` HTTP 400 `Input collision on slot` whenever a workflow defines an `ExpectedInput` whose normalized base label prefixes `"taskbrief..."` (`@[backend_v2/services/ingress/smart_ingress_resolver.py#L40-L263]`). Furthermore, `StudioPromptBlockService.create_prompt_block_draft` hardcodes `PromptBlockCategory.SYSTEM_RULE`, `SystemRulePromptBlock.instruction_text` enforces `min_length=1` when non-null, `TheoryGrounding.source_url` is mandatory when `theory_grounding` is non-null, and `StudioAuthValidator.enforce_modification_rights` forbids tenant `ADMIN` edits/deletes on `ROOT_SYSTEM` blocks while permitting `clone_prompt_block`.
   - **Architectural Justification:**
     - Preserve `PromptBlockCategory.TASK_DEFINITION` and `PromptBlockCategory.RUNTIME_VARIABLES` in `StudioPromptBlockService.create_prompt_block_draft`.
     - Evolve `execution_assignments` within the closed 15-table PostgreSQL 19 schema (`ZORM004`, `ZORM006`, `ZORM007`) by adding nullable `task_brief_id UUID REFERENCES prompt_blocks(id) ON DELETE SET NULL` (with UUIDv7 `CHECK` constraint and idempotent `ALTER TABLE execution_assignments ADD COLUMN IF NOT EXISTS task_brief_id UUID REFERENCES prompt_blocks(id) ON DELETE SET NULL;`), propagating `task_brief_id` and hydrated `TaskAssignmentBriefDTO` (`TaskAssignmentBriefDto`) across `ExecutionAssignment`, `ExecutionAssignmentCreateDTO`, `ExecutionAssignmentBatchCreateDTO`, `ExecutionAssignmentResponseDTO`, and `ExecutionAssignmentPreviewDTO` with 1:1 Freezed DTO parity.
     - Validate on assignment creation that any non-null `task_brief_id` resolves via `IPromptBlockRepository` to an accessible `PromptBlockCategory.TASK_DEFINITION` block (`service_tenant_rbac_isolation_mandate`), and project `TaskAssignmentBriefDTO` onto `ExecutionAssignmentPreviewDTO` and `ExecutionAssignmentResponseDTO` without touching `locked_inputs.dynamic_inputs`.
     - Expose `_TaskBriefsManagementCard` (`Key('org_task_briefs_card')`) in `OrganizationIamSettingsView` using typed `PromptBlockCategory.taskDefinition.id`, mapping empty `instructionText` to `null` and empty `sourceUrl` to `theoryGrounding: null`, enabling Edit/Delete exclusively when `currentUser.role == UserRole.root || block.organizationId == activeOrgId` while keeping Clone enabled on all visible Task Briefs, and invalidating `organizationTaskBriefsProvider` on `ROOT` organization switch (`tenant_data_isolation`).

3. **Finding A — Authentic Firebase Auth + Mandatory TOTP 2FA JIT Onboarding Handshake (`@[backend_v2/services/execution/assignment_service.py#L1165-L1234]`, `@[client_app_v2/lib/features/auth/data/auth_repository.dart#L50-L393]`, `@[client_app_v2/lib/features/execution/views/task_assignment_portal_view.dart#L74-L628]`):**
   - **Root Cause:** `TaskAssignmentPortalView` previously sent the raw password text from `onboardingTokenController` as `firebaseToken`, failing `fb_auth.verify_id_token` with HTTP 401. Moreover, in live environments (`settings.require_mfa == True`), newly provisioned Firebase users created via `createUserWithEmailAndPassword` have `emailVerified == false` (blocking client-side `multiFactor.getSession()` with `unverified-email`) and lack an enrolled TOTP second factor (causing `onboard_assignee` to raise `AuthenticationError(ErrorCodes.MFA_REQUIRED)`), while Firebase Email Enumeration Protection causes `signInWithEmailAndPassword` to return `'invalid-credential'` instead of `'user-not-found'` for unregistered emails. Additionally, `AppException.unauthorized()` in `@[client_app_v2/lib/core/error/app_exception.dart#L72-L78]` is a zero-argument factory emitting `errorCode == 'AUTHENTICATION_FAILED'`, and `AppException.validation(...)` emits `errorCode == 'VALIDATION_FAILED'`.
   - **Architectural Justification:**
     - In `ExecutionAssignmentService._verify_onboarding_firebase_token`, verify `IDENTITY_MISMATCH` (`token_email == expected_email.lower()`) before MFA enforcement; when the token email matches the invited `expected_email` and `email_verified` is not `True`, mark `email_verified=True` via `await asyncio.to_thread(fb_auth.update_user, uid_str, email_verified=True)` (awaiting coroutine return values via `inspect.iscoroutine` for hermetic `AsyncMock` compatibility) before invoking `_enforce_firebase_mfa_claim`. Because possession of the single-use 256-bit emailed `raw_token` plus matching email proves inbox ownership, this unblocks client-side Firebase TOTP enrollment without weakening `MFA_REQUIRED`!
     - Extract reusable Firebase MFA SSOT helpers (`prepareEnrollmentForCurrentUser`, `resolveChallengeAndGetIdToken`, `enrollTotpAndGetIdToken`) in `AuthRepository` (`ssot_reuse_mandate`) and implement `authenticateForTaskOnboarding` handling `signInWithEmailAndPassword`, `createUserWithEmailAndPassword` fallback on both `'user-not-found'` and `'invalid-credential'` (mapping `'email-already-in-use'` back to `Left(AppException.unauthorized())`), `MultiFactorResolver` challenge verification (`await firebase.TotpMultiFactorGenerator.getAssertionForSignIn(...)`), and in-portal TOTP enrollment when `onboardAssignee` returns `MFA_REQUIRED` (`reloadUser: true` -> display `task_portal_totp_secret_text` -> verify 6-digit TOTP -> re-submit `onboardAssignee`).

4. **Finding B — Standalone `TaskAssignmentConfigDialog`, Localized Input Chips & Verified Dispatch Summary (`@[client_app_v2/lib/features/execution/views/new_execution_view.dart#L784-L1232]` & `@[client_app_v2/lib/features/settings/presentation/organization_iam_settings_view.dart#L467-L680]`):**
   - **Root Cause:** `Key('org_new_task_assignment_btn')` in `OrganizationIamSettingsView` previously only refreshed `organizationAssignmentsProvider`, while `_TaskAssignmentConfigDialog` was private to `NewExecutionView`, displayed raw `item.inputKey` strings on `FilterChip`s, and formatted `/task/${_createdSingle!.id}` using the public `tsk_<hex32>` entity ID instead of the emailed secret 256-bit `raw_token`.
   - **Architectural Justification:** Promote `TaskAssignmentConfigDialog` with standalone `Workflow`, `OutputProfile`, and `TaskDefinitionPromptBlock` (`taskBriefId`) dropdown selectors, localized `ExpectedInput.label` `FilterChip`s, verified dispatch confirmation (`assignedEmail`, `emailDeliveryStatus`, `id`), and cohort dispatch summary CSV export.

5. **Finding D — End-to-End Eager Base64 Extraction for Portal File Uploads (`@[backend_v2/models/auth.py#L1332-L1341]`, `@[backend_v2/api/routers/execution/executions.py#L311-L344]`, `@[backend_v2/services/execution/assignment_service.py#L666-L731]`, `@[client_app_v2/lib/features/execution/views/task_assignment_portal_view.dart#L74-L628]`):**
   - **Root Cause:** `ExecutionAssignmentDraftDTO.draft_inputs` and `ExecutionAssignmentSubmitDTO.submitted_inputs` were typed strictly as `WorkflowInputs`, whose `validate_no_base64` validator rejects `Base64Attachment` (`content_base64`) with HTTP 422 at the FastAPI boundary! Even if accepted, `save_execution_assignment_draft` lacked `DocumentExtractionServiceDep`, and `merge_assignment_inputs` returned `WorkflowInputs` causing `ExecutionIngressService._resolve_and_extract_inputs` (`isinstance(payload.raw_inputs, WorkflowInputsIngress)`) to skip `DocumentExtractionService.process_ingress_payload`! On the Flutter side, `WorkflowInputValue` is a single-constructor `@freezed abstract class` exposing `textValue` and `fileValue` (`RawFileInputDto?`), and `file_picker` requires `FilePicker.platform.pickFiles(...)`.
   - **Architectural Justification:** Type `ExecutionAssignmentDraftDTO.draft_inputs` and `ExecutionAssignmentSubmitDTO.submitted_inputs` as `WorkflowInputsIngress | WorkflowInputs`, inject `doc_service: DocumentExtractionServiceDep` into `save_execution_assignment_draft` -> `ExecutionService.save_draft_inputs` -> `ExecutionAssignmentService.save_draft_inputs`, and add `ExecutionAssignmentService._normalize_assignee_ingress_inputs` to eagerly extract any `Base64Attachment` entries via `await doc_service.process_ingress_payload(...)` into `WorkflowInputs` (`base64_amnesia_protocol`) before persisting `ExecutionAssignment.draft_inputs` or dispatching `ExecutionCreate`. Wire `FilePicker.platform.pickFiles` and `WorkflowInputValue.file(filename: ..., contentBase64: ...)` (`fileVal.fileValue`) in `TaskAssignmentPortalView`.
