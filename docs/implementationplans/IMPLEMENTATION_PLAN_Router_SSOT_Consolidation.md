# IMPLEMENTATION PLAN: Router SSOT Consolidation & Universal CRUD+Clone Enforcement (`reports.py`, `workflows.py`, `system_configs.py`)

## 1. Objective & Architectural Background

Enforce 100% compliance with `single_router_ssot_mandate`, `crud_and_clone_lifecycle_standard_mandate`, `opaque_stripe_id_ssot_constant_mandate`, `slug_data_relation_ban`, `the_no_legacy_mandate`, and `@[ki_router_ssot_and_crud_clone_lifecycle.md]` across all non-IAM FastAPI routers in `backend_v2/api/routers/` and their corresponding Flutter Dio API clients in `client_app_v2/lib/core/api/`.

Forensic audit and CRUD + Delete dry runs across `backend_v2/api/routers/`, `backend_v2/services/studio/`, and `backend_v2/database/repositories/` identified five non-IAM router Single Source of Truth (SSOT) and gold-standard lifecycle anomalies alongside missing delete-protection and OpenAPI CI guardrails:
1. **Empty Dead Router (`system_configs.py`)**: `@[backend_v2/api/routers/studio/system_configs.py]` defines an empty `APIRouter(prefix="/system-configs", tags=["Studio - System Configs"])` with zero route handlers, creating a deceptive shadow module alongside `@[backend_v2/api/routers/system/configs.py]`, `@[backend_v2/api/routers/studio/model_registry.py]`, and `@[backend_v2/api/routers/studio/mcp_gateways.py]`.
2. **Duplicate `/system/system/hooks` Prefix (`system/health.py`)**: `@[backend_v2/api/routers/system/health.py]` defines `APIRouter(prefix="/system")` while mounted inside `@[backend_v2/api/routers/system/__init__.py]` (`APIRouter(prefix="/system")`), producing a doubled `/api/v2/system/system/hooks` path instead of `/api/v2/system/hooks`.
3. **Split `Workflow` Entity Router (`execution/workflows.py` vs. `studio/workflows.py`)**: `Workflow` CRUD, clone (`POST /{id}/clone`), simulation, and extension discovery live in `@[backend_v2/api/routers/studio/workflows.py]` (`/api/v2/studio/workflows`), whereas `GET /{workflow_id}/ui_schema` is isolated in a separate single-endpoint router `@[backend_v2/api/routers/execution/workflows.py]`. Furthermore, `@[client_app_v2/lib/core/api/workflow_client.dart]` calls `_dio.get('/api/v2/workflows/$workflowId/ui_schema')` on an `apiClient` whose `baseUrl` already terminates with `/api/v2/`.
4. **Triple-Router & Dual-Decorated `ReportArtifact` Module (`execution/reports.py` & `main.py`)**: `@[backend_v2/api/routers/execution/reports.py]` defines three separate `APIRouter` instances (`router`, `external_router`, and `execution_reports_subrouter`), attaches duplicate `@router.<method>("/execution/...", include_in_schema=False)` shadow decorators on every endpoint, mounts `execution_reports_subrouter` inside `@[backend_v2/api/routers/execution/executions.py]`, mounts `reports_router` in both `@[backend_v2/api/routers/execution/__init__.py]` and `@[backend_v2/main.py]`, and mounts `external_reports_router` under both `/api/v1` and `/api/v2` in `@[backend_v2/main.py]`.
5. **Legacy Studio Routers & Services Missing HTTP-Boundary `OPAQUE_STRIPE_ID_REGEX`, `ID_MISMATCH`, Dynamic Matrix Draft Creation (`category_id=matrix`), Clone Unlocking (`is_system_core=False`), and 3-Layer Delete Protection (`workflows.py`, `steps.py`, `prompt_blocks.py`, `model_registry.py`, `mcp_gateways.py`)**:
   - Only `@[backend_v2/api/routers/output_profiles.py]` currently enforces `Annotated[str, Path(pattern=OPAQUE_STRIPE_ID_REGEX)]` on path parameters and Fail-Fast `ErrorCodes.ID_MISMATCH` validation on `PUT /{id}` at the router boundary; all 5 older Studio blueprint routers must be upgraded to 100% parity.
   - `@[backend_v2/services/studio/prompt_block_service.py]` (`create_prompt_block_draft`) hardcodes `SystemRulePromptBlock`, preventing dynamic creation of a `MatrixPromptBlock` when clicking "New Matrix" in `@[client_app_v2/lib/features/studio/views/matrices_master_view.dart]` and `@[client_app_v2/lib/features/studio/views/studio_dashboard_view.dart]`.
   - `@[backend_v2/services/studio/workflow_service.py]` (`clone_step`) retains `is_system_core=True` when cloning a system-core step, causing the cloned step to remain locked against editing and deletion instead of becoming an unlocked specialist step (`is_system_core=False`), while `slug` remains a purely informational field (`slug_data_relation_ban`).
   - Delete dry-run verification exposed five missing delete-protection guards:
     a) `@[backend_v2/services/studio/system_config_service.py]` passes `allow_system=True` to `enforce_modification_rights` in `create_mcp_gateway_draft`, `delete_mcp_gateways`, and `discover_mcp_gateway_tools`, allowing a non-`ROOT` Tenant `ADMIN` to delete global `ROOT_SYSTEM` MCP Gateways; and `delete_system_config` allows deleting the last remaining `SystemConfigModelRegistry`.
     b) `@[backend_v2/services/studio/prompt_block_service.py]` (`delete_prompt_block`) allows deleting foundational `PromptBlockCategory.PROTOCOL` blocks without raising `ErrorCodes.SYSTEM_PROTECTED_RESOURCE` (`403`).
     c) `@[backend_v2/database/repositories/components/prompt_block.py]` (`delete_prompt_block`) checks obsolete V1 field `"prompt_blocks" in s` instead of V2 `Step` fields (`role_block_id`, `extraction_protocol_block_id`, `execution_persona_block_id`, `criteria_block_ids`), allowing in-use Matrices and Role/Persona blocks to be deleted while referenced by Steps.
     d) `@[backend_v2/services/studio/workflow_service.py]` (`delete_step`) omits checking whether the `Step` is actively referenced in `Workflow.steps` (`rule.task_blueprint == id`) before delegating to the repository.
     e) `@[backend_v2/services/studio/output_profile_service.py]` (`delete_output_profile`) allows deleting an `OutputProfile` that is actively configured as a workflow's `default_profile_id`.
