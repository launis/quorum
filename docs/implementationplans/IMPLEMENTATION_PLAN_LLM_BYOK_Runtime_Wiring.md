# IMPLEMENTATION PLAN: LLM Provider BYOK Runtime Credential Wiring

## 1. Objective & Architectural Background

### Technical Objective
Connect the existing Dual-Tier BYOK secret governance layer (`SecretService.resolve_llm_key` in `@[backend_v2/services/auth/secret_service.py#L306-L352]`) and provider factory credential binding (`LLMFactory.create_provider` in `@[backend_v2/llm/provider/provider_factory.py#L31-L324]` and `LiteLLMProvider` in `@[backend_v2/llm/provider/litellm_provider.py#L75-L453]`) end-to-end into `LLMClient.from_tier`, Phase 1 DAG execution (`ExecutionIngressService._persist_and_enqueue_execution` and `execute_engine_retry_stage`), and Phase 2 report synthesis (`generate_profile_synthesis_and_pdf_task` and `build_variance_metrics_and_task`).

### Root Cause Analysis
1. **Unbridged `LLMClient` Credential Resolution (`@[backend_v2/llm/client.py#L51-L944]`)**:
   - `SecretService.resolve_llm_key(organization_id, provider)` is already implemented and verified: it queries PostgreSQL 19 `tenant_secrets` for `(organization_id, SecretScope.LLM_PROVIDER, provider.value)`, decrypts `SecretStorageMode.ENVELOPE_KMS` or fetches `SecretStorageMode.CLOUD_SECRET_MANAGER` payloads with zero fallback on decryption failure (`ConfigurationError` with `ErrorCodes.SECRET_RESOLUTION_FAILED`), and resolves the platform key (`Settings.google_api_key`, `Settings.openai_api_key`, `Settings.anthropic_api_key`, or `"vertex-adc-managed"` for `LLMProvider.VERTEX_AI`) when no tenant BYOK record is configured.
   - `LLMFactory.create_provider` (`@[backend_v2/llm/provider/provider_factory.py#L31-L324]`) and `LiteLLMProvider` (`@[backend_v2/llm/provider/litellm_provider.py#L75-L453]`) already accept `organization_id` and `resolved_credential: ResolvedCredentialDTO | None = None`, isolating semaphore and router cache keys per `(model_name, organization_id)` and injecting `call_kwargs["api_key"]` at generation time without leaking tenant keys into shared router state.
   - However, `LLMClient.__init__` (`@[backend_v2/llm/client.py#L51-L944]`) and `LLMClient.from_tier` (`@[backend_v2/llm/client.py#L51-L944]`) do not accept `organization_id` or `secret_service`, do not invoke `SecretService.resolve_llm_key`, and do not forward `organization_id` or `resolved_credential` into `LLMFactory.create_provider` inside `LLMClient.run_structured_task` (`@[backend_v2/llm/client.py#L51-L944]`) or `LLMClient.run_chat` (`@[backend_v2/llm/client.py#L51-L944]`).
2. **Unpopulated `GlobalContextVarsDTO.organization_id` at Execution Ingress (`@[backend_v2/services/execution/ingress_service.py#L701-L791]`)**:
   - `GlobalContextVarsDTO` (`@[backend_v2/models/dtos/global_context.py#L31-L146]`) already declares `organization_id: str | None = None` and `initiator_id: str | None = None`, and `workflow_bootstrap_stage.py` (`@[backend_v2/services/orchestrator/dag_executor/workflow_bootstrap_stage.py#L331-L540]`) preserves `exec_record.metadata.global_context_vars` into `StrategyContext.global_context_vars`.
   - However, `ExecutionIngressService._persist_and_enqueue_execution` (`@[backend_v2/services/execution/ingress_service.py#L378-L791]`) instantiates `ExecutionMetadata` without populating `global_context_vars=GlobalContextVarsDTO(organization_id=initiator.organization_id, initiator_id=initiator.id, target_locale=payload.target_locale, profile_id=resolved_profile_id)`.
3. **Missing `organization_id` Forwarding in Phase 1 Stage 3 & Phase 2 Synthesis (`@[backend_v2/services/orchestrator/strategies/llm_strategy/engine_retry_stage.py#L433-L629]`, `@[backend_v2/workers/synthesis_worker.py#L97-L661]`, `@[backend_v2/workers/variance_synthesis.py#L290-L426]`)**:
   - In `engine_retry_stage.py`, `_run_optional_mcp_retrieval` (`#L188`) instantiates `ToolDispatcher(gateways=active_gateways)` without `organization_id`, and `execute_engine_retry_stage` (`#L479-L485`) calls `LLMClient.from_tier(...)` without `organization_id`.
   - In `synthesis_worker.py` (`#L308-L313`) and `variance_synthesis.py` (`#L395-L400`), `LLMClient.from_tier(...)` is called without passing `organization_id` from `execution.organization_id` / `execution.raw_inputs.organization_id`.
