# IMPLEMENTATION PLAN: SlowAPI Dependency Removal (TenantRateLimitService Cutover) and Hermetic google.genai Module Restoration

## 1. Objective & Architectural Background

This implementation plan executes the approved Tier 8 Feature Audit (`feature_audit_slowapi_removal_and_genai_mock_restoration.md`) across two structural root causes identified in GitHub CI on Python 3.14:

1. **`slowapi` Dependency Eradication & `TenantRateLimitService` Single-Pipeline Cutover:**
   - `@[pyproject.toml#L38-L38]` previously depended on `slowapi>=0.1.9`, an unmaintained third-party package that calls `asyncio.iscoroutinefunction(func)` (deprecated in Python 3.14 and slated for removal in Python 3.16) when decorating `exchange_firebase_token` in `@[backend_v2/api/routers/iam/auth.py#L50-L84]`.
   - `@[backend_v2/core/redis_security.py#L353-L672]` (`TenantRateLimitService`) already implements the Fail-Closed Redis sliding-window rate limiter with `enforce_auth_edge_rate_limit` (`@[backend_v2/core/redis_security.py#L603-L672]`) and `PUBLIC_AUTH_EDGE_SCOPES` containing `"POST /api/v2/iam/auth/exchange"` backed by `settings.auth_edge_rpm_limit`.
   - When the sliding-window threshold is exceeded, `TenantRateLimitService._raise_rate_limit_exceeded` (`@[backend_v2/core/redis_security.py#L425-L470]`) logs `ErrorCodes.RATE_LIMIT_EXCEEDED` and raises `TokenLimitExceededError` (`@[backend_v2/exceptions.py#L819-L832]`, HTTP 429). Because `TokenLimitExceededError` inherits from `AppException` (`@[backend_v2/exceptions.py#L345-L442]`), `app_exception_handler` (`@[backend_v2/main.py#L355-L383]`) serializes it directly into an RFC 7807 `application/problem+json` response.
   - We therefore `[DELETE]` `@[backend_v2/core/rate_limit.py#L25-L78]` and `[DELETE]` `@[backend_v2/tests/unit/core/test_rate_limit.py#L13-L31]`, remove `slowapi` from `@[pyproject.toml#L38-L38]` and `@[uv.lock]` (under explicit user authorization `PERMISSION GRANTED to remove slowapi from pyproject.toml and uv.lock`), delete `rate_limit_exception_handler` from `@[backend_v2/main.py#L355-L383]`, delete `_resolve_exchange_rate_limit` from `@[backend_v2/api/routers/iam/auth.py#L50-L84]`, and inject `rate_limit_service: TenantRateLimitServiceDep` into `exchange_firebase_token` (`@[backend_v2/api/routers/iam/auth.py#L50-L84]`).
   - **QGR016 Guardrail Compliance:** In `@[scripts/_ast_guardrails.py#L2459-L2490]` (`QuorumGuardrailVisitor.visit_IfExp`), a ternary expression with a string literal fallback (`request.client.host if request.client is not None else ""`) triggers a fatal `QGR016` violation (`Banned ternary lazy fallback`). Therefore, `exchange_firebase_token` (`@[backend_v2/api/routers/iam/auth.py#L50-L84]`) extracts `client_ip` using an explicit `if request.client is not None:` statement (`client_ip = ""` followed by `if request.client is not None: client_ip = request.client.host`) before calling `await rate_limit_service.enforce_auth_edge_rate_limit(client_ip=client_ip, endpoint_scope="POST /api/v2/iam/auth/exchange")`.

2. **Hermetic `sys.modules` Reference Restoration & `mypy --strict` Compliance in `test_ai_studio_adapter.py`:**
   - `@[backend_v2/tests/unit/llm/adapters/test_ai_studio_adapter.py#L99-L130]` (`cleanup_genai_mock`) previously overwrote `sys.modules["google.genai"]` and `sys.modules["google.genai.types"]` at pytest collection time and executed `del sys.modules[...]` followed by `importlib.import_module("google.genai.types")` during module teardown, triggering Python 3.14's `DeprecationWarning: '_UnionGenericAlias' is deprecated and slated for removal in Python 3.17` from `google/genai/types.py:42`.
   - We refactor `@[backend_v2/tests/unit/llm/adapters/test_ai_studio_adapter.py#L71-L89]` and `@[backend_v2/tests/unit/llm/adapters/test_ai_studio_adapter.py#L99-L130]` to pre-import and snapshot the canonical `google`, `google.genai`, `google.genai.types`, and `google.genai.errors` module objects once via `importlib.import_module` inside a scoped `warnings.catch_warnings()` block, install `mod_genai` and `mod_genai_types` inside `cleanup_genai_mock` (`scope="module"`, `autouse=True`) before `yield`, and restore the exact original module objects in `finally:` after `yield` without `del` or `importlib.import_module`. Furthermore, we replace `sys._mock_genai_client` with a typed module-level `_mock_genai_client: MagicMock` variable, declare `errors: ModuleType` on `MockGenAIModule` (`@[backend_v2/tests/unit/llm/adapters/test_ai_studio_adapter.py#L71-L89]`), and ensure all test fixtures in `@[backend_v2/tests/unit/llm/adapters/test_ai_studio_adapter.py]` pass `mypy --strict` when audited directly via `scripts/backend_audit_loop.py`.

## 5. Architectural Safeguards & Verification Plan (ISTQB Test Matrix)

### Automated Unit & Structural Tests
- **Scenario 1 (Happy Path - Token Exchange Within Edge Rate Limit):**
  - **Input:** `POST /api/v2/iam/auth/exchange` (`exchange_firebase_token`) called with `request.client = Address("127.0.0.1", 50000)` and `TenantRateLimitService` backed by in-memory Redis when counter is `1 <= settings.auth_edge_rpm_limit`.
  - **Expected Output:** `enforce_auth_edge_rate_limit` returns `1` and `exchange_firebase_token` returns `TokenExchangeResponseDTO` with `expires_in_seconds == 900`.
- **Scenario 2 (Negative Path 1 - Missing Client IP Metadata on Exchange Request):**
  - **Input:** `exchange_firebase_token` called with `request.client = None` (resolving `client_ip = ""`).
  - **Expected Output:** `TenantRateLimitService.enforce_auth_edge_rate_limit` logs `ErrorCodes.VALIDATION_FAILED` and raises `AppException` with `status_code == 400` and `error_code == ErrorCodes.VALIDATION_FAILED`.
- **Scenario 3 (Negative Path 2 - Boundary Value Violation `auth_edge_rpm_limit + 1`):**
  - **Input:** `exchange_firebase_token` called on the `(settings.auth_edge_rpm_limit + 1)`-th request within the 60-second window for `127.0.0.1`.
  - **Expected Output:** `TenantRateLimitService.enforce_auth_edge_rate_limit` logs `ErrorCodes.RATE_LIMIT_EXCEEDED` and raises `TokenLimitExceededError` with `status_code == 429` and `error_code == ErrorCodes.RATE_LIMIT_EXCEEDED`, serialized by `app_exception_handler` as RFC 7807 `application/problem+json`.
- **Scenario 4 (Negative Path 3 - Fail-Closed Redis Unavailability on Exchange Request):**
  - **Input:** `exchange_firebase_token` called with `TenantRateLimitService(redis=None)`.
  - **Expected Output:** Raises `ServiceUnavailableError` with `status_code == 503` and `error_code == ErrorCodes.SERVICE_UNAVAILABLE`.
