# BUG FIX PLAN: PostgreSQL 19 `system_configs` `NULL` `name` Hydration Failure, Preflight Schema Verification & Live Seed Synchronization

## 1. Root Cause Analysis (The 5 Whys) & Architectural Justification

### Observed Failure (`@[backend_debug.log#L62-L192]` & `@[backend_debug.log#L1229-L1335]`)
When the Flutter desktop client queries `GET /api/v2/studio/model-registry/` or `GET /api/v2/studio/mcp-gateways/`, FastAPI returns HTTP 500 `Internal Server Error` due to an unhandled `pydantic_core._pydantic_core.ValidationError` inside an `asyncio.TaskGroup` `ExceptionGroup`:
```text
1 validation error for mcp_gateways
name
  Input should be a valid string [type=string_type, input_value=None, input_type=NoneType]
```

### The 5 Whys Trace
1. **Why 1 — Why did `GET /api/v2/studio/model-registry/` crash with a `ValidationError` on `mcp_gateways`?**
   `SystemConfigRepository.get_all_model_registries` (`@[backend_v2/database/repositories/system.py#L54-L65]`) executes `await self.driver.query("system_config", [Filter("type", "==", "model_registry")])`. `PostgresStorageDriver.query` (`@[backend_v2/database/postgres/storage_driver.py#L185-L555]`) delegates to `list_collection_documents_rows` (`@[backend_v2/database/postgres/entity_adapter/seed_and_collection_stage.py#L262-L283]`), which fetches and hydrates every row in `system_configs` via `hydrate_system_config_row(r)` (`@[backend_v2/database/postgres/entity_adapter/iam_and_system_stage.py#L912-L970]`) before filtering by `type` in memory.
2. **Why 2 — Why did `hydrate_system_config_row` fail on the `mcp_gateways` row (`sys_0195f3a00000700080008172bda70c86`)?**
   In the live local PostgreSQL 19 `system_configs` table, row `0195f3a0-0000-7000-8000-8172bda70c86` has `name = NULL` (`None` in Python), which violates the required `name: Annotated[str, Field(min_length=1)]` contract on `SystemConfigMCPGateways` (`@[backend_v2/models/domain/system_config.py#L377-L437]`). Furthermore, `hydrate_system_config_row` does not catch `ValidationError` to log a structured RFC 7807 `logger.error` and raise `AppException(ErrorCodes.VALIDATION_FAILED)`, allowing a raw `ValidationError` to escape unhandled.
3. **Why 3 — Why did `system_configs` in PostgreSQL 19 still contain `name = NULL` after commit `dc68c0aa2` added `"name": "Tavily MCP Gateway"` to `seed_data.json`?**
   Prior to commit `dc68c0aa2`, `system_configs` was created with a nullable `name` column and `upsert_system_config_row` bound `$2 = None` (`NULL`) for `SystemConfigMCPGateways` rows. During the execution of `IMPLEMENTATION_PLAN_BYOK_SECRET_PERSISTENCE_AND_UI.md`, only `uv run python backend_v2/seed/run_seed.py local --dry-run` (in-memory validation) was executed; Step `6_reseed` of `@[.agents/rules/03_seed_vault.md]` (`uv run python backend_v2/seed/run_seed.py local` without `--dry-run`) was omitted, leaving the pre-existing `NULL` row in PostgreSQL 19.
4. **Why 4 — Why did `apply_migrations()` not enforce `NOT NULL` and `DROP DEFAULT` on `system_configs.name` for pre-existing tables?**
   In `@[backend_v2/database/migrations/001_pg19_uuidv7_schema.sql#L82-L99]`, changing `name TEXT DEFAULT 'Default Model Registry'` to `name TEXT NOT NULL` inside `CREATE TABLE IF NOT EXISTS system_configs` is a no-op on a pre-existing `system_configs` table. No idempotent `ALTER TABLE system_configs ALTER COLUMN name DROP DEFAULT;` or conditional `ALTER TABLE system_configs ALTER COLUMN name SET NOT NULL;` evolution block was added, and `_seed_postgres` in `@[backend_v2/seed/run_seed.py#L276-L340]` did not re-apply migrations after upserting seed rows to lock `SET NOT NULL`.
5. **Why 5 — Why did FastAPI startup pre-flight (`_validate_database_preflight` in `@[backend_v2/main.py#L134-L179]`) log `Pre-flight PostgreSQL 19 database validation PASSED` at `17:59:33` when `system_configs` contained an un-reseeded `NULL` `name` row?**
   Because `verify_seed_table_counts_rows` in `@[backend_v2/database/postgres/entity_adapter/seed_and_collection_stage.py#L219-L259]` only executed `SELECT count(*) AS row_count FROM system_configs` without hydrating the `system_configs` rows via `list_collection_documents_rows(conn, timeout, "system_configs")`. Consequently, stale pre-migration rows passed startup pre-flight undetected and crashed at runtime.

### Architectural Justification
- **Fail-Fast Hydration & RFC 7807 Dual-Reporting (`universal_fail_fast`, `rfc7807_dual_reporting_mandate`)**: Catching `ValidationError` in `hydrate_system_config_row` (`@[backend_v2/database/postgres/entity_adapter/iam_and_system_stage.py#L912-L970]`), logging a structured `logger.error` with `ErrorCodes.VALIDATION_FAILED` and `entity_id=cfg_id`, and raising `AppException` ensures every persistence boundary failure produces deterministic RFC 7807 telemetry and honors `get_collection_document_row`'s `AppException` contract.
- **Pre-Flight `system_configs` Schema Hydration Verification (`preflight_schema_assertion_mandate`)**: Extending `verify_seed_table_counts_rows` (`@[backend_v2/database/postgres/entity_adapter/seed_and_collection_stage.py#L219-L259]`) to execute `await list_collection_documents_rows(conn, timeout, "system_configs")` whenever `expected` requires `system_configs` (or `system_config`) `>= 1` guarantees that `_validate_database_preflight` (`@[backend_v2/main.py#L134-L179]`) and `_seed_postgres` (`@[backend_v2/seed/run_seed.py#L276-L340]`) immediately detect any un-reseeded or schema-incompatible `system_configs` row at startup and fail fast with explicit `run_seed.py` remediation instructions.
- **Idempotent DDL Constraint Evolution & Live Re-Seed (`zero_orm_ddl_column_evolution_and_preflight_mandate`, `vault_mutation_protocol`)**: Adding `DELETE FROM system_configs WHERE name IS NULL;`, `ALTER TABLE system_configs ALTER COLUMN name DROP DEFAULT;`, and `ALTER TABLE system_configs ALTER COLUMN name SET NOT NULL;` in `@[backend_v2/database/migrations/001_pg19_uuidv7_schema.sql#L82-L108]`, calling `apply_migrations()` after `seed_collection_batch` in `@[backend_v2/seed/run_seed.py#L276-L340]`, and executing `uv run --no-sync --offline python backend_v2/seed/run_seed.py local` purges any pre-migration `NULL`-name rows, updates the live PostgreSQL 19 `system_configs` rows, and permanently locks the `NOT NULL` constraint on pre-existing databases.
