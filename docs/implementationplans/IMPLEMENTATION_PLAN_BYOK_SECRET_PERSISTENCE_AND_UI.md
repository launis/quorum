# IMPLEMENTATION PLAN: BYOK Secret PostgreSQL 19 Persistence, Storage Mode Parity, Canonical MCP Gateway `name` Parity & Target Selector UI

## 1. Objective & Architectural Background

In the Organization & IAM settings view (`@[client_app_v2/lib/features/settings/presentation/organization_iam_settings_view.dart#L1291-L1545]`), the **BYOK-avaimet ja pilvisalaisuudet** (`_ByokSecretsCard`) panel and MCP Gateway domain models exhibit four architectural gaps across backend persistence, DTO serialization, canonical entity naming, and frontend target selection:

1. **Unwired Process-Scoped `SecretService` Persistence, RAM Fallback & Missing Physical Deletion**:
   - Although the PostgreSQL 19 `tenant_secrets` table (`001_pg19_uuidv7_schema.sql`) and `PostgresEntityAdapter` (`upsert_tenant_secret`, `get_tenant_secret`, `list_tenant_secrets`, `delete_collection_document`) are implemented, `get_secret_service()` in `@[backend_v2/services/auth/secret_service.py#L964-L973]` instantiates `SecretService()` with `entity_adapter=None` and no Unit of Work factory. Consequently, secrets saved via `PUT /api/v2/iam/organizations/{org_id}/secrets` fall back to `SecretService._local_secrets` RAM and vanish upon backend restart or across separate worker processes (`worker.py`).
   - Furthermore, `SecretService.delete_tenant_secret` in `@[backend_v2/services/auth/secret_service.py#L240-L292]` only records the deleted ID in `self._deleted_secret_ids` and removes it from `self._local_secrets` without executing a physical `DELETE` against the `tenant_secrets` table via `EntityPersistencePort.delete_collection_document("tenant_secrets", secret_id)`.
   - Per `single_pipeline_invariant_mandate` and `zero_backward_compatibility_planning_ban`, the in-memory `_local_secrets` dictionary and `_deleted_secret_ids` tombstone set MUST be eradicated from `SecretService`. Persistence MUST flow exclusively through `EntityPersistencePort` or a `QuorumUnitOfWork` transaction (`uow.entities.upsert_tenant_secret`, `uow.entities.get_tenant_secret`, `uow.entities.list_tenant_secrets`, and `uow.entities.delete_collection_document`), raising `ConfigurationError` (`ErrorCodes.CONFIGURATION_ERROR`) Fail-Fast if neither `entity_adapter` nor `uow_factory` is configured. To honor the Tripartite Layer Firewall (`QGR017`), `backend_v2/database/interfaces.py` will expose `UnitOfWorkFactory`, `register_default_uow_factory`, and `get_registered_uow_factory` (registered with `create_unit_of_work` by `backend_v2/database/factory.py` in production and with an isolated `InMemoryUnitOfWork` in `backend_v2/tests/conftest.py` during unit tests).

2. **Missing Required `storage_mode` Field on `TenantSecretCreateDTO` / `TenantSecretCreateDto`**:
   - `_ByokSecretsCard` renders the `Tallennustila` (`org_secret_storage_mode_dropdown`) selector for `SecretStorageMode` (`envelopeKms` vs `cloudSecretManager`), but `TenantSecretCreateDto` in `@[client_app_v2/lib/features/settings/domain/models/tenant_secret_dto.dart#L173-L186]` and `TenantSecretCreateDTO` in `@[backend_v2/models/auth.py#L1440-L1453]` omit `storage_mode`. Adding `storage_mode` as a required field (with zero default fallback per `zero_defaults_mandate` and `silent_json_fallbacks`) directly to `TenantSecretCreateDTO` and `TenantSecretCreateDto` and reading `payload.storage_mode` as the single source of truth in `SecretService.upsert_tenant_secret` eliminates duplicate parameter coalescing.

3. **Missing Canonical `name` Field on `SystemConfigMCPGateways` & `McpGateway` (and Legacy SQL `DEFAULT` on `system_configs.name`)**:
   - In `@[backend_v2/database/migrations/001_pg19_uuidv7_schema.sql#L82-L98]`, the `system_configs` table already declares a `name` column (`name TEXT DEFAULT 'Default Model Registry'`), and `_UPSERT_SYSTEM_CONFIG_SQL` / `_GET_SYSTEM_CONFIG_SQL` / `_LIST_SYSTEM_CONFIGS_SQL` in `@[backend_v2/database/postgres/entity_adapter/iam_and_system_stage.py]` already select and bind `name` (`$2`).
   - However, while `SystemConfigModelRegistry` (`@[backend_v2/models/domain/system_config.py#L210-L260]`) declares `name`, `SystemConfigMCPGateways` (`@[backend_v2/models/domain/system_config.py#L376-L434]`) and Flutter `McpGateway` (`@[client_app_v2/lib/features/studio/models/mcp_gateway.dart#L113-L133]`) omitted `name`, `hydrate_system_config_row` / `upsert_system_config_row` (`@[backend_v2/database/postgres/entity_adapter/iam_and_system_stage.py#L911-L951]`) dropped `name` for `mcp_gateways`, and `sys_0195f3a00000700080008172bda70c86` in `@[backend_v2/seed/seed_data.json#L209-L218]` omitted `"name"`. That omission is the exact reason UI components previously fell back to displaying `gateway.id` or `gateway.slug`.
   - Every persisted domain entity in `system_configs` MUST have both a canonical `id` (`sys_<hex32>`) for relational binding and a required human-readable `name` (`min_length=1`, with zero default value in Python/Dart and `name TEXT NOT NULL` with zero SQL `DEFAULT` in `001_pg19_uuidv7_schema.sql`).

4. **Raw Text `target_identifier` Input, Missing Scope-Target Validation & `ROOT`-Only MCP Gateway Listing**:
   - When `SecretScope.mcpGateway` is selected in `_ByokSecretsCard`, `SecretService.resolve_mcp_credential` matches `target_identifier == gateway.id` (`sys_0195f3a00000700080008172bda70c86`), whereas the UI forces the administrator to type a raw string into `org_secret_target_field` without listing configured MCP gateways or `LLMProvider` identifiers. Because `slug` is strictly an informational attribute (`slug_data_relation_ban`) and never a relational identifier or primary title, `SecretService.upsert_tenant_secret` MUST strictly validate `target_identifier` against `EntityPrefix.SYSTEM_CONFIG` (`sys_<hex32>`) for `SecretScope.MCP_GATEWAY` and `LLMProvider` enum values for `SecretScope.LLM_PROVIDER` (raising `AppException` with `ErrorCodes.VALIDATION_FAILED` on mismatch), and `_ByokSecretsCard` MUST replace the free-text field exclusively with a scope-aware `DropdownButtonFormField<String>` (`org_secret_target_dropdown`) displaying `'${gw.name} (${gw.id})'` and binding `value: gw.id` with zero text-field fallback.
   - Additionally, `StudioSystemConfigService.list_mcp_gateways` in `@[backend_v2/services/studio/system_config_service.py#L393-L404]` restricts `GET /api/v2/studio/mcp-gateways` to `[UserRole.ROOT]`, preventing tenant `ADMIN` users from fetching available MCP gateways to select in `_ByokSecretsCard`.
