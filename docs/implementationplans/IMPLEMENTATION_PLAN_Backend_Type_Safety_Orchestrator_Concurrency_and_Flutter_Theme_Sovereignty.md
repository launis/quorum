### Zero Dict Creation Invariant & Exhaustive Dict Justification Ledger

> [!IMPORTANT]
> **Mandate**: In accordance with the User Mandate and Rule `no_naked_dicts_in_state` (`01-python-backend.md`), **NOT A SINGLE RUNTIME DICTIONARY MAY BE CREATED** in business logic, state reduction, or service pipelines (specifically: ban on `d = {}`, `dict(...)`, `d[k] = v`, `_EvaluativeMatricesWrapperDTO`, and ad-hoc dictionary accumulators).
> 
> Across the entire scope of this implementation, exactly **FOUR (4)** strictly typed dictionary fields are permitted in Pydantic DTOs and domain models. Every single one is mathematically and architecturally justified below:
> 
> 1. **`SynthesisMetadataDTO.step_metrics: Annotated[dict[str, StepTelemetryEntryDTO] | None, Field(...)]`**
>    - **Why it exists:** Maps dynamic Opaque Stripe step identifiers (`stp_[a-f0-9]{16}`) to their strongly typed execution telemetry DTO (`StepTelemetryEntryDTO`).
>    - **Why a static Pydantic model is impossible:** Step IDs are generated dynamically per workflow DAG topology and cannot be hardcoded as static attribute names.
>    - **Why it is safe & compliant:** It completely replaces the loose `dict[str, JsonValue]` open-JSON bag. Values are 100% strictly validated Pydantic V2 DTOs (`StepTelemetryEntryDTO`). Zero naked dictionaries.
> 
> 2. **`TranslationResponseDTO.translated_data: Annotated[dict[str, str], Field(...)]`**
>    - **Why it exists:** Maps arbitrary UI chrome and template localization keys to translated text values returned by the dynamic translation hook.
>    - **Why a static Pydantic model is impossible:** Localization keys vary dynamically across reports and UI components.
>    - **Why it is safe & compliant:** It eliminates the open-JSON `dict[str, JsonValue]` type. Both keys and values are strictly typed primitives (`str -> str`). Zero unvalidated payloads.
> 
> 3. **`GlobalContextVarsDTO.evaluative_matrices: Annotated[dict[str, float] | None, Field(...)]`**
>    - **Why it exists:** Maps dynamic prompt block identifiers (`blk_[a-f0-9]{16}`) to computed normalized matrix scores (`float`, $0.0 \le s \le 1.0$).
>    - **Why a static Pydantic model is impossible:** Prompt block IDs are dynamic relational entities configured in Quorum Studio and cannot be statically declared as model attributes.
>    - **Why it is safe & compliant:** Both keys and values are strictly typed primitives (`str -> float`). Replaces the duct-tape string-keyed dictionary injection into `dynamic_inputs` and eliminates `_EvaluativeMatricesWrapperDTO`.
> 
> 4. **`ExecutionRecord.step_states: dict[str, ExecutionStep]` (updated in `transition_step`)**
>    - **Why it exists:** Pre-existing SSOT domain property on `ExecutionRecord` providing $O(1)$ step lookup by canonical step ID.
>    - **Why dictionary creation occurs:** In `transition_step`, constructing a shallow updated mapping `{**self.step_states, step_id: updated_step}` is required by Pydantic V2 to produce an immutable, frozen model copy (`.model_copy(update={"step_states": ...})`) without in-place mutation.
>    - **Why it is safe & compliant:** Values are validated `ExecutionStep` domain models. Zero runtime state leakage.
> 
> **Zero Other Dictionaries:** In all other 13 delta branches in `state_reducer.py` (`passivity_detected`, `archivist_precedents`, `shuffled_atoms`, `profiler_metrics`, `distillation`, `scoring`, `interaction_analysis`, `bibliography`, `sanitization`, `llm_anomaly_retry_requested`, `input_control_ratio`, `integrity_verified_output`, `step_metadata`), strictly **ZERO DICTIONARIES ARE CREATED**. Payloads are routed directly to typed Pydantic fields via `model_copy(update={field: payload})`.
>
> **Test Fixture Zero Untyped Dict Invariant & QGR029 Enforcement**:
> Rule `QGR029` extends the Zero Dict Mandate to test fixtures, strictly forbidding `@pytest.fixture` functions from annotating or returning raw untyped dictionaries representing domain models or DTOs. Test data setup must utilize strongly typed Pydantic V2 models generated by Polyfactory (`model_factories.py`). Raw dictionaries in tests are permitted exclusively as input payloads in negative schema validation tests (`pytest.raises(ValidationError): Model.model_validate({...})`) or HTTP endpoint payloads (`client.post(..., json={...})`), where untyped payloads are mathematically required to prove validation rejection.
