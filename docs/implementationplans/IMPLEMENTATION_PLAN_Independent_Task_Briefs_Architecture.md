# IMPLEMENTATION PLAN: Independent `task_briefs` Database Table, Seed Collection & Frontend Architecture

## 1. Objective & Architectural Background

Human-facing reusable task briefs and case descriptions (*"Uudelleenkäytettävät tehtävänannot ja tapauskuvaukset"*) were previously stored inside the polymorphic `prompt_blocks` table under `"category_id": "task_definition"`. That same discriminator value simultaneously represented 11 active internal DAG step instruction blocks (`block_taskanalyst` through `block_taskperformativity` plus `synthesis_generation_block`) and 2 unreferenced legacy synthesis blocks (`blk_0195f3a0000070018a2b3c4d5e6f7a8b` `exec_coach_synthesis` and `blk_0195f3a0000070088b7a6f5e4d3c2b1a` `analytical_synthesis`). Because `_TaskBriefsManagementCard` and `TaskAssignmentConfigDialog` filtered `PromptBlock` records by `TaskDefinitionPromptBlock`, internal LLM agent step rules leaked directly into human assignment pickers and IAM management views, while `execution_assignments.task_brief_id` pointed to `prompt_blocks(id)` instead of a dedicated domain table.

To enforce Single Source of Truth (SSOT) table sovereignty in 1:1 alignment with `workflows`, `steps`, `output_profiles`, and `prompt_blocks`:
1. **Dedicated 16th PostgreSQL 19 Table & Seed Collection (`task_briefs`)**: Introduce `EntityPrefix.TASK_BRIEF = "tbr"` (`tbr_<32_hex_uuidv7>`), immutable `TaskBrief(V2CoreBase)` domain schema, `TaskBriefResponseDTO(BaseResponseDTO, TaskBrief)` response boundary, `CREATE TABLE IF NOT EXISTS task_briefs` with native PostgreSQL 19 `uuidv7()` primary keys and `VIRTUAL` generated `created_at` timestamps, Zero-ORM `PostgresEntityAdapter` stage operations, `ITaskBriefRepository` (`TaskBriefRepositoryImpl`), 5-operation `StudioTaskBriefService` (`create_draft`, `get`, `list`, `save`, `delete`, `clone`), and canonical router `/api/v2/studio/task-briefs`.
2. **Normalized Foreign Key & Assignment Resolution**: Point `execution_assignments.task_brief_id` to `task_briefs(id) ON DELETE SET NULL`, migrate pre-existing foreign keys idempotently in `@[backend_v2/database/migrations/001_pg19_uuidv7_schema.sql]`, format/parse `task_brief_id` with `EntityPrefix.TASK_BRIEF` in `PostgresEntityAdapter`, and resolve task briefs via `ITaskBriefRepository` in `ExecutionAssignmentService` and `ExecutionService`.
3. **Purge `TASK_DEFINITION` from `PromptBlockCategory` & Sanitize `@[backend_v2/seed/seed_data.json]`**:
   - Reclassify the 11 active internal DAG step instruction blocks from `"category_id": "task_definition"` to `"category_id": "system_rule"` with 100% preservation of `instruction_text` (`prompt_preservation_mandate`).
   - Delete the 2 unreferenced legacy synthesis blocks (`blk_0195f3a0000070018a2b3c4d5e6f7a8b` and `blk_0195f3a0000070088b7a6f5e4d3c2b1a`) and remove the obsolete hardcoded ID exemption in `@[backend_v2/tests/unit/test_seed_architectural_guardrails.py#L26-L49]`.
   - Remove `TASK_DEFINITION` from `PromptBlockCategory` across Python and Dart so `prompt_blocks` exclusively models AI prompt engineering building blocks (specifically and exhaustively: `matrix`, `system_rule`, `execution_persona`, `agent_role`, `protocol`, `runtime_variables`).
   - Seed 2 authentic bilingual workflow-aligned `TaskBrief` records (`tbr_0195f3a00000700d8a1b2c3d4e5f6001` and `tbr_0195f3a00000700d8a1b2c3d4e5f6002`) matching workflow expected inputs (`product_text`, `chat_log`, `reflection_text`).
4. **Frontend (`client_app_v2`) 1:1 DTO & CRUD+Clone Parity**: Define `@Freezed(equal: false) abstract class TaskBrief` with `@JsonSerializable(disallowUnrecognizedKeys: true)` and `@StrictOpaqueIdConverter()`, register `"taskbriefresponsedto": "taskbrief"` and `"taskbrief": "taskbriefresponsedto"` in `@[scripts/audit_dto_parity.py]`, add `StudioClient` CRUD+Clone endpoints for `studio/task-briefs`, and migrate `_TaskBriefsManagementCard`, `_EditTaskBriefDialog`, and `TaskAssignmentConfigDialog` to `TaskBrief`.
