# IMPLEMENTATION PLAN: Symmetric Flutter Micro/Macro Hardening Pipeline, Tripartite Layer & Protocol Guardrails, Dart 3.11 Strict Analyzer, Retry Feedback Loop & Creative Skill Context Offloading

## 1. Objective & Architectural Background

Forensic analysis of unattended multi-wave hardening runs (`@[scripts/auto_hardening_runner.py]`, `@[scripts/flutter_audit_loop.py]`, `@[scripts/_dart_guardrails.py]`, `@[scripts/_ast_guardrails.py]`), Dart 3.11 / Flutter 3.41 analyzer settings (`@[client_app_v2/analysis_options.yaml]`), backend architectural rules (`@[.agents/rules/01-python-backend.md]`), and creative System 2 skills (`@[.agents/skills/tier0-create-plan/SKILL.md]`, `@[.agents/skills/tier0-create-epic/SKILL.md]`, `@[.agents/skills/tier8-audit-feature/SKILL.md]`) identified nine high-leverage architectural bottlenecks across execution speed, tripartite interface isolation, static type strictness, retry intelligence, process lifecycle hygiene, and context window preservation:

1. **Asymmetric Micro/Macro Quality Gate on Frontend Targets:**
   While backend targets (`HardeningGate.BACKEND`) execute a fast single-file `--micro --no-logfire` pass per file and defer the full repository audit to a single completion gate (`run_macro_quality_gate`), frontend targets (`HardeningGate.FRONTEND`) invoke `scripts/flutter_audit_loop.py <target> --build --strict` on every individual `.dart` file. This unconditionally runs `flutter gen-l10n` and `dart run build_runner build -d` 185 times across files that contain zero code-generation annotations, while omitting execution of the target's isolated unit test (`client_app_v2/test/unit/..._test.dart`).
2. **Missing Unit Test Enforcement in Per-File Flutter Gate:**
   Because `@[scripts/flutter_audit_loop.py#L62-L92]` only supports running the global `flutter test --coverage` suite when `--test` is passed, per-file frontend quality gates do not verify that the corresponding `*_test.dart` file exists and passes.
3. **Dart 3.11 / Riverpod 4.0 / Freezed 3.2 Guardrail Contradiction & Missing Strict Analyzer Flags:**
   In `@[scripts/_dart_guardrails.py#L232-L371]` (specifically lines 338–351, `DGR010`), the remediation message instructs agents to use legacy `.when()` or `.maybeWhen()`, directly contradicting `freezed_when_ban` in `@[.agents/rules/02_flutter_desktop.md]`, which mandates Dart 3 native `switch (asyncState) { AsyncData(:final value) => ... }` pattern matching. Additionally, `@[scripts/_dart_guardrails.py#L232-L371]` does not flag deprecated Flutter Impeller `.withOpacity(` calls (replaced by `.withValues(alpha: ...)`), and `@[client_app_v2/analysis_options.yaml]` lacks Dart 3.11 strict type-checking modes (`strict-casts: true`, `strict-inference: true`, `strict-raw-types: true`).
4. **Missing Tripartite Layer & Protocol Import Firewall (PostgreSQL ↔ Pydantic ↔ Python):**
   While `QGR028` prevents service-layer re-validation of repository outputs and `QGR017` bans dead legacy drivers, `@[scripts/_ast_guardrails.py#L2718-L2858]` (`visit_Import`) and `@[scripts/_ast_guardrails.py#L2718-L2858]` (`visit_ImportFrom`) do not statically enforce the Tripartite Interface Boundary across the three backend pillars:
   - **Pydantic (`backend_v2/models/`):** Pure schema and validation layer — must never perform runtime imports from `asyncpg`, `backend_v2.database`, `backend_v2.services`, `backend_v2.hooks`, `backend_v2.api`, or `backend_v2.workers`.
   - **PostgreSQL (`backend_v2/database/`):** Pure Zero-ORM persistence and graph engine — must never import upward from `backend_v2.hooks`, `backend_v2.api`, `backend_v2.workers`, or `backend_v2.services` (outside `backend_v2.services.storage` in `execution.py`).
   - **Python Business & Routing (`backend_v2/services/`, `backend_v2/hooks/`, `backend_v2/api/routers/`):** Pure domain orchestration — must communicate with persistence exclusively through `typing.Protocol` contracts in `backend_v2.database.interfaces` and never directly import `asyncpg`, `backend_v2.database.postgres`, `backend_v2.database.in_memory`, `backend_v2.database.repositories`, `backend_v2.database.repository`, `backend_v2.database.driver`, or `backend_v2.database.factory`.
5. **Blind Retry Loop Without Failure Context (`last_error` Feedback Gap):**
   In `@[scripts/auto_hardening_runner.py#L1437-L1535]` (`process_target_with_retries`), when Attempt 1 fails `run_quality_gate`, `execute_circuit_breaker_rollback` restores the workspace to a clean state and stores `last_error = gate_res.output`, but Attempt 2 invokes `execute_subagent_pass` with the identical blind prompt without passing `last_error`. Feeding the truncated failure output into retry attempts prevents the subagent from repeating the identical compiler, guardrail, or test mistake.
6. **Orphaned Windows MCP Child Processes & Uncommitted Rollback Leak:**
   Each headless `agy` invocation on Windows spawns child MCP servers (`dart.exe language-server`, `node.exe`). Currently, `@[scripts/auto_hardening_runner.py#L887-L958]` (`execute_subprocess_with_tree_kill`) runs `taskkill /F /T /PID` only on `TimeoutExpired`, allowing orphaned MCP child processes to accumulate across 185 targets. Additionally, `@[scripts/auto_hardening_runner.py#L887-L958]` (`WorkspaceSnapshotDTO`) and `@[scripts/auto_hardening_runner.py#L887-L958]` (`execute_circuit_breaker_rollback`) do not record or restore `head_sha` if a subagent performs an internal `git commit` before failing the outer quality gate.
7. **Incomplete Git Staging in `mark_tracker_and_checkpoint`:**
   `@[scripts/auto_hardening_runner.py#L541-L585]` stages only `[target_file, cleaned_tracker]`, leaving newly created unit tests (`resolve_target_unit_test_files`) and sibling `.g.dart`/`.freezed.dart` artifacts unstaged.
8. **Unprotected Windows S0 Modern Standby Suspension:**
   Unattended multi-hour runs on Windows 11 are suspended by S0 Modern Standby idle timers unless the runner asserts a native Win32 thread execution state wake-lock (`ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_AWAYMODE_REQUIRED`).
9. **Context Window Dilution in Creative System 2 Skills (`tier0-*`, `tier8-audit-feature`):**
   Creative planning and architecture skills currently force the primary agent to manually run AST line-bound extraction commands and multi-file searches inside the main conversation context window. Adding deterministic symbolic AST auto-binding (`@[file.py#symbol_name]` -> `@[file.py#Lnn-mm]` via `--fix`) to `@[scripts/audit_markdown_boundaries.py#L164-L713]` and delegating multi-file reconnaissance to isolated `research` subagents preserves 85–90% of the primary context window for creative System 2 reasoning.
