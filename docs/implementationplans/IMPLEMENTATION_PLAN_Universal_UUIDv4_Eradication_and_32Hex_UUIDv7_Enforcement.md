# IMPLEMENTATION PLAN: Universal Eradication of Legacy UUIDv4 Generators & Full 32-Hex RFC 9562 UUIDv7 Enforcement

## 1. Objective & Architectural Background

Following the universal 32-character hexadecimal RFC 9562 UUIDv7 cutover (`OPAQUE_STRIPE_ID_REGEX = r"^([a-z]{2,5})_[a-fA-F0-9]{32}$"` and `parse_prefixed_uuid7(..., enforce_v7=True)` in `@[backend_v2/models/core_base.py#L230-L279]`), residual side-paths in both the Flutter desktop client (`client_app_v2/lib/`) and the Python backend (`backend_v2/`) still invoke legacy `Uuid().v4()` and `uuid.uuid4()` generators:

1. **Flutter Studio Client Side-Path Failures (`Uuid().v4()` and 16-Hex Truncations)**:
   - `@[client_app_v2/lib/features/studio/views/widgets/workflow/workflow_steps_tab.dart]` (`_addStep` at line 43 and `_copyStep` at line 74) generates `Uuid().v4()` and truncates `sr_` identifiers to 16 hex characters (`uuidHex.characters.take(16)`), which fails backend 32-hex `StepRule.id` validation upon saving a workflow.
   - `@[client_app_v2/lib/features/studio/views/widgets/profile/blocks/matrix_graphs_block_card.dart]` (`_addGroup` at line 165) and `@[client_app_v2/lib/features/studio/views/widgets/profile/layout_editor_card.dart]` (`_addGroup` at line 30) generate `grp_` identifiers via `const Uuid().v4().replaceAll('-', '').substring(0, 16)` (violating both `DGR008` `.substring()` and backend 32-hex `MatrixSynthesisGroup.id` validation).
   - `@[client_app_v2/lib/features/studio/utils/workflow_cloner.dart]` (line 54) generates 16-hex `sr_` IDs via `_uuid.v4().replaceAll('-', '').substring(0, 16)` (violating `DGR008`).
   - `@[client_app_v2/lib/features/studio/models/prompt_block.dart]` (`TDAAssertion.create` at line 172) generates a 32-hex `tda_` ID using `const Uuid().v4()`, embedding version nibble `4` instead of RFC 9562 version `7`.
   - `@[client_app_v2/lib/features/studio/views/widgets/scale_editor_modal.dart]` (`_previewScalePrompt` at line 173) uses a 16-zero placeholder `'blk_0000000000000000'`, which fails backend 32-hex `PromptBlockBase.id` validation during scale prompt preview.
   - `@[client_app_v2/lib/utils/json_converters.dart]` (`StrictOpaqueIdConverter` at line 58) still permits `{16,32}` hex characters instead of enforcing `{32}`.

2. **Backend Side-Path Failures (`uuid.uuid4()` Version 4 & Truncated Hex)**:
   - Domain model `default_factory` lambdas in `@[backend_v2/models/auth.py]` (`Organization.id` at line 90, `User.id` at line 235), `@[backend_v2/models/domain/base.py]` (`UsageRecord.id` at line 286), `@[backend_v2/models/domain/matrix.py]` (`TDAAssertion.tda_id` at line 130), `@[backend_v2/models/chunking.py]` (`Chunk.id` at line 42), and `@[backend_v2/models/state.py]` (`TraceEvent.event_id` at line 163, `WorkflowState.execution_id` at line 316) call `uuid.uuid4()`.
   - Service, repository, hook, and LLM modules (`@[backend_v2/services/auth/organization_service.py#L79-L140]`, `@[backend_v2/services/auth/user_service.py#L96-L221]`, `@[backend_v2/services/usage_service.py#L121-L213]`, `@[backend_v2/services/orchestrator/two_pass_atomizer.py#L254-L357]`, `@[backend_v2/services/orchestrator/dag_executor/workflow_bootstrap_stage.py#L321-L380]`, `@[backend_v2/services/mcp/dispatcher.py#L529-L627]`, `@[backend_v2/services/drivers/local_file_driver.py#L105-L169]`, `@[backend_v2/database/repositories/audit.py]`, `@[backend_v2/database/repositories/execution.py#L31-L95]`, `@[backend_v2/database/repositories/knowledge.py]`, `@[backend_v2/hooks/linguistics.py#L77-L222]`, `@[backend_v2/hooks/llm.py#L25-L159]`, `@[backend_v2/hooks/references.py#L33-L82]`, `@[backend_v2/llm/client.py#L127-L309]`, `@[backend_v2/llm/mock_data.py#L411-L491]`, `@[backend_v2/llm/provider/litellm_response_stage.py#L62-L284]`) invoke `uuid.uuid4()`, which either produces version-4 UUIDs rejected by `PostgresEntityAdapter` (`parse_prefixed_uuid7(..., enforce_v7=True)`) or 8/16-hex truncated strings.

This plan extracts a canonical `generate_uuid7()` helper in `@[backend_v2/models/core_base.py]` and `generateOpaqueUuid7(String prefix)` in `@[client_app_v2/lib/utils/json_converters.dart]`, migrates every production and test-factory `uuid4()` / `.v4()` call to RFC 9562 UUIDv7, and adds static AST (`QGR030`) and Dart (`DGR008`) guardrails banning `uuid4` and `.v4(`.
