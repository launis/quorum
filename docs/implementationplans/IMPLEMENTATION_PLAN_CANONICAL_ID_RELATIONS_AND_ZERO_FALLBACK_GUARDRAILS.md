# IMPLEMENTATION PLAN: Canonical `id` Relational Sovereignty, Universal Entity Naming, `slug` Identification Ban, Zero-Default & Zero-Fallback Static Guardrails

## 1. Objective & Architectural Background

Quorum V2 enforces three foundational data and execution invariants across its Tripartite Architecture (PostgreSQL 19, Pydantic V2, and Python 3.14):

1. **Single Canonical `id` Identification, Universal Human-Readable Entity Naming & Relational Policy (`id_backend_generation_authority_mandate`, `opaque_stripe_id_mandate`, `direct_id_relational_mandate`):**
   - Every persisted domain entity across `backend_v2/models/domain/`, `backend_v2/seed/seed_data.json`, and `backend_v2/database/migrations/001_pg19_uuidv7_schema.sql` uses a single canonical primary key field strictly named `id` (formatted in Python/JSON as a 32-hex RFC 9562 UUIDv7 Opaque Stripe ID matching `OPAQUE_STRIPE_ID_REGEX = r"^([a-z]{2,5})_[a-fA-F0-9]{32}$"` and stored in PostgreSQL 19 as `id UUID PRIMARY KEY DEFAULT uuidv7()` with `CHECK (uuid_extract_version(id) = 7)`).
   - Every named domain entity table in PostgreSQL 19 (`CANONICAL_NAMED_ENTITY_TABLES`: `organizations`, `users`, `system_configs`, `prompt_blocks`, `steps`, `workflows`, `output_profiles`, `report_artifacts`) and every seed entity collection in `seed_data.json` (`organizations`, `users`, `system_config`, `prompt_blocks`, `steps`, `workflows`, `output_profiles`) MUST declare its canonical human-readable display field (`name`, `label`, or `title`) for UI presentation, strictly separated from `id` (which is used exclusively for identification and relational binding) and `slug` (optional technical namespace metadata).
   - All cross-entity relations are bound exclusively through canonical `id` fields: in PostgreSQL 19 via `REFERENCES <target_table>(id)`, and in Python/JSON/Dart models via `*_id` / `*_ids` fields (`organization_id`, `workflow_id`, `mcp_gateway_id`, `model_registry_id`, `default_profile_id`, `role_block_id`, `extraction_protocol_block_id`, `execution_persona_block_id`, `criteria_block_ids`, `variance_target_block`, `user_role_target_block`, `target_blocks`) referencing the target entity's `.id`.

2. **Absolute `slug` Identification & Relational Ban (`slug_data_relation_ban`, `relational_slug_ban`, `matrix_slug_identification_ban`):**
   - `slug` is strictly an informational metadata attribute and never a relational identifier or substitute for an entity's `id` or `name`.
   - `slug` is forbidden from acting as a primary key, foreign key, query filter (`Filter("slug", ...)` / `QueryCondition("slug", ...)`), SQL `WHERE` / `JOIN ... ON` / `UNIQUE` predicate, dictionary lookup key (`{x.slug: ...}`), identifier comparison (`x.slug == "literal"` or `x.slug == target_id`), or diagnostic identifier in `logger.*` and `AppException` calls.

3. **Zero-Default, Zero-Fallback & Single-Pipeline Sovereignty (`zero_defaults_mandate`, `zero_service_layer_fallbacks`, `single_pipeline_invariant_mandate`, `zero_backward_compatibility_planning_ban`):**
   - Critical domain, identity, naming, relational, and creation DTO fields (`id`, `*_id`, `*_ids`, `slug`, `name`, `label`, `title`, `storage_mode`, `updated_by`, `created_by`, `target_identifier`) must never declare hardcoded scalar, string, or Enum default values (`= "default"`, `= "Default Model Registry"`, `= SecretStorageMode.ENVELOPE_KMS`, `= SYSTEM_ROOT_USER_ID`, `Field(default=...)`) in Python/Pydantic or SQL `DEFAULT` clauses in PostgreSQL 19 DDL, and service/router methods must never mutate missing values into defaults via `if value is None: value = default`.
   - Services and API routers must operate through a single deterministic pipeline backed by `QuorumUnitOfWork` and `EntityPersistencePort`.
   - Test-environment pipeline bifurcation (`"PYTEST_CURRENT_TEST"` checks in `backend_v2/services/` or `backend_v2/api/`) and in-memory shadow fallback dictionaries (`self._local_*`, `self._deleted_*`, `self._memory_*` in `backend_v2/services/`) are banned under `QGR030`.
