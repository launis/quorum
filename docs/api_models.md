# API Models & Data Schemas (V5.1)

This document details the strict **Pydantic V2** data models used throughout the Cognitive Quorum system. All data exchange is strictly typed (`ConfigDict(strict=True, extra="ignore")`) to ensure hallucination-free execution and proper integration with the Server-Driven UI (SDUI) architecture.

---

## 🟢 Core State (`backend.models.state`)

### `WorkflowState` (Event Sourcing)
The system uses an **Event Sourcing** pattern. The state is an immutable log of events, not a mutable blackboard.

| Field | Type | Description |
| :--- | :--- | :--- |
| `execution_id` | `UUID` | Unique identifier for this execution instance. |
| `workflow_id` | `str` | ID of the workflow definition. |
| `status` | `Literal` | `pending`, `running`, `completed`, `failed`. |
| `execution_trace` | `list[TraceEvent]` | **Immutable log** of all steps, inputs, reasoning, and outputs. |
| `context_variables` | `dict[str, Any]` | Current snapshots of context variables (the "Folded State"). |

### `TraceEvent`
An atomic unit of history.

| Field | Type | Description |
| :--- | :--- | :--- |
| `event_id` | `UUID` | Unique event ID. |
| `timestamp` | `datetime` | UTC timestamp. |
| `step_name` | `str` | Name of the step that generated this event. |
| `event_type` | `Literal` | `input`, `reasoning`, `decision`, `error`, `output`. |
| `content` | `dict` | Structured content payload (polymorphic). |
| `reasoning` | `ReasoningTrace` | **Hidden Chain-of-Thought** (separate from content). |

## 🔒 Domain Models (`backend.models.domain`)

Domain models represent the absolute "truth" of the AI's cognitive reasoning. They are heavy, semantic, and do not contain UI-specific formatting or localization.

### `ToulminComponent` (Logician Agent)
Represents a formal argumentation structure.
- `claim`: The core assertion.
- `warrant`: The logical bridge.
- `data`: The evidence supporting the claim.
- `backing`: Support for the warrant.
- `rebuttal`: Exceptions to the claim.
- `qualifier`: The degree of certainty.

### `InteractionAnalysis` (Interaction Agent)
Represents the user's agency and behavior.
- `role_classification`: The user's role (e.g., Driver, Passenger).
- `input_control_ratio`: Quantitative measure of user control vs LLM control.
- `strategy`: The overarching approach taken by the user.

### `ProfilerMetrics` & `BehavioralMetrics` (Profiler Agent)
Represents psychological and biases analysis.
- `automation_bias`: Whether the user is over-reliant on the AI.
- `say_do_gap`: Consistency between stated goals and actual behavior.

## 🎭 View Models / SDUI Enums (`backend.models.view`)

View models (Display models) are generated by the **BFF Transformers**. They are lean, type-safe, and explicitly designed for the Flutter frontend to consume. They never contain translated text, only localization Enum keys or raw native text.

### `ToulminDisplay`
Mapped from `ToulminComponent` by `LogicDomainTransformer`.
| Field | Type | Notes |
| :--- | :--- | :--- |

| `data` | `str` | Included for UI rendering. |
| `backing` | `str` | Included for UI rendering. |
| `rebuttal` | `str` | Included for UI rendering. |
| `qualifier` | `str` | Included for UI rendering. |

### `DriverProfileDisplay`
Mapped from `InteractionAnalysis` by `ProfilingTransformer`.
| Field | Type | Notes |
| :--- | :--- | :--- |
| `role_classification` | `str` | Strict Enum key for I18N. |
| `input_control_ratio` | `str` | Included for UI rendering (e.g., "75%"). |
| `strategy` | `str` | Raw native text strategy. |

### Localization Enum Keys
The BFF Transformers convert raw boolean/string states into specific I18N keys to satisfy the **No-String Mandate**.
- `automation_bias` -> `BIAS_DETECTED` or `BIAS_NONE`.
- `say_do_gap` -> `GAP_DETECTED` or `GAP_NONE`.

## 🚦 Component REST APIs (Strict Separation)

Each specific configuration entity has its own strictly typed API Controller and Pydantic validation model.

| Entity | REST URI | Pydantic Model | Description |
| :--- | :--- | :--- | :--- |
| **Logic Matrices** | `/config/matrices` | `MatrixComponentResponse` | Scoring rubrics with strictly numerical Scales. |
| **Active Agents** | `/config/agents` | `AgentComponentResponse` | Model boundaries, prompts, and execution rules. |
| **Output Configs** | `/config/outputs` | `ConfigComponentResponse` | Defines final XAI outputs. The *only* location where `ui_hints` are permitted. |
| **Text Components** | `/config/components` | `TextComponentResponse` | Generic pure text rules and instructions. |

This isolation ensures that a schema error instantly triggers an RFC 7807 `422 Unprocessable Entity` via Pydantic on the boundary, protecting downstream logic and the UI from processing poisoned state data.
