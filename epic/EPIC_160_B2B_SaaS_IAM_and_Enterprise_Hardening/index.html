    EPIC 160: B2B SaaS IAM, Token Exchange & Enterprise Hardening Architecture

    [!NOTE] Scientific & Industrial Validation (2025-2026) Enterprise B2B SaaS and multi-tenant agentic AI architectures in 2025-2026 converge on four foundational security standards validated by IETF specifications and cloud security frameworks: 1. RFC 8693 OAuth 2.0 Token Exchange, Mandatory MFA (NIST SP 800-63B AAL2) & Stateless Session Upgrade: Forwarding external Identity Provider (IdP) tokens across internal service boundaries or querying a relational database on every HTTP request introduces 15–50 ms of per-request tail latency and couples domain schemas to third-party identity vendors. Exchanging the external IdP credential (Firebase ID Token) once at the API edge (POST /api/v2/iam/auth/exchange) after verifying mandatory Multi-Factor Authentication (firebase.sign_in_second_factor claim) for a short-lived (15-minute), internally signed Quorum Local JWT embedding verified tenant, role, and MFA claims (sub, org, role, mfa) reduces per-request authorization latency to < 0.1 ms in RAM while decoupling downstream services from the authentication vendor. 2. RFC 9562 UUIDv7 Primary Keys & Dual-Layer Tenant Isolation: Using arbitrary external string identifiers (Firebase UID) as SQL primary keys causes random B-Tree page splits and index fragmentation in PostgreSQL. Enforcing RFC 9562 monotonic uuidv7() primary keys formatted as PrefixedUUID7 (usr_<hex32>, org_<hex32>, inv_<hex32>, sec_<hex32>) preserves B-Tree sequential write locality while keeping firebase_uid as an indexed VARCHAR(128) UNIQUE NOT NULL lookup column. Furthermore, in asynchronous asyncpg connection pools, relying solely on session state (SET LOCAL) risks cross-tenant pool contamination; pairing explicit parameterized SQL predicates (WHERE organization_id = $1) with transactional RESET quorum.current_org cleanup guarantees deterministic SOC2 and GDPR tenant isolation. 3. Dual-Tier Envelope Encryption & BYOK Secrets Governance (LLM + MCP): Enterprise tenants require Bring Your Own Key (BYOK) sovereignty across both foundational LLM providers (LiteLLMProvider in @[backend_v2/llm/provider/litellm_provider.py#L74-L429]) and external Model Context Protocol (MCP) tool gateways (GenericMCPClient in @[backend_v2/services/mcp/generic_mcp_client.py#L54-L806]). Storing credentials via Cloud Secret Manager resource references (projects/.../secrets/...) or Envelope Encryption (Data Encryption Keys wrapped by Key Encryption Keys in Cloud KMS / AES-256-GCM inside tenant_secrets) with request-scoped pydantic.SecretStr unwrapping prevents cross-tenant credential bleed and guarantees zero plaintext exposure in logs, DTOs, or MCPAuditTrace records. 4. Fail-Closed Redis Kill-Switch & Edge FinOps Rate Limiting: Stateless short-lived JWTs require an out-of-band revocation mechanism to terminate compromised sessions before the 15-minute expiration window. Checking an O(1) Redis revocation key (revoked:usr:<id> with 900-second TTL) under a strict Fail-Closed policy (503 Service Unavailable when Redis is unreachable) alongside per-tenant sliding-window tpm_limit and rpm_limit token buckets protects both enterprise data and LLM FinOps budgets at the API edge.
